> **핵심 주장** — **처음 보는 집에서 일하는 로봇을 만들기 위해 필요한 것은 타깃 로봇 데이터를 끝없이 늘리는 것이 아닌, 성격이 다른 지식원을 각자 맞는 층위에 먹이는 학습 레시피입니다.** π₀.₅는 다른 로봇, 웹, 서브태스크 라벨, 사람의 음성 지시를 한 모델에 공동학습시킵니다. 그리고 그 모델이 "해야 할 서브태스크를 먼저 텍스트로 말한 뒤, 그 말에 따라 움직이도록" 만들어, 학습 데이터에 없던 가정에서 주방과 침실을 정리합니다.

---

## 들어가며

VLA(Vision-Language-Action) 모델의 표준 레시피는 웹에서 사전학습된 VLM을 가져와 로봇 시연으로 모방학습시키는 것입니다. RT-2, OpenVLA, π₀가 모두 이 틀 안에 있고, 언어 지시를 따르는 능력과 복잡한 조작 능력을 보여 왔습니다. 그런데 이 모델들은 대체로 **학습 데이터와 비슷한 환경에서 평가**됩니다. 로봇이 실험실을 나와 처음 보는 집에 들어가면 어떤 일이 생기는지가 남는 질문입니다.

π₀.₅는 이 질문에 정면으로 답하려는 논문입니다. **미리 말해 두면, 이 논문의 기여는 새로운 네트워크 모듈이 아닌 학습 레시피입니다.** 아키텍처는 π₀와 거의 같습니다. 달라진 것은 무엇을 출력하게 하는가, 무엇으로 학습시키는가, 학습 단계마다 액션을 어떻게 표현하는가 세 가지입니다.

이 글에서는 논문의 논지를 따라가면서, 각 설계 결정이 **왜** 그 모양인지를 필요한 개념과 함께 정리했습니다.

## 1. 문제 — 처음 보는 집은 왜 어려운가

### 1.1 일반화에는 층위가 있다

로봇이 처음 보는 주방을 치우라는 지시를 받았다고 해 보겠습니다. 논문은 이때 필요한 일반화를 세 층위로 나눕니다.

| 층위 | 예 | 필요한 것 |
|---|---|---|
| **ⓐ 스킬** | 칼이나 접시를 집음 | 충분히 다양한 장면·물체를 덮는 데이터 |
| **ⓑ 조합** | 익힌 스킬을 새 순서나 새 방식으로 씀 | 태스크 구조에 대한 이해, 스킬의 재조합 |
| **ⓒ 의미** | 어느 서랍을 열지, 조리대 위 무엇이 건조대일지 판단함 | 사전지식에 기반한 장면 의미 이해 |

**이 구분이 중요한 이유는 층위마다 필요한 지식의 출처가 다르기 때문입니다.** ⓐ는 로봇 데이터를 더 다양한 환경에서 모으면 얻을 수 있습니다. 반면 ⓑ는 태스크의 구조를, ⓒ는 세상에 대한 상식을 요구하며, 로봇 시연만으로 이 둘을 채우기는 어렵습니다.

### 1.2 기존 방식은 어디서 막히는가

논문의 Related Work가 정리하는 선행 연구의 성과와 한계는 다음과 같습니다.

| 접근 | 성과 | 한계 |
|---|---|---|
| 로봇 데이터의 환경 다양성 확대 | 집기·서랍 열기 같은 단순 스킬이 새 환경으로 일반화 | 주방 정리 같은 장기 태스크는 가능한 시나리오를 brute-force로 덮을 수 없음 |
| 태스크 특화 가정 (grasp 예측, 모델 기반 계획·제어) | 새 집까지 폭넓게 일반화 | 물건 집기 같은 좁은 primitive에 국한됨 |
| 대규모 다도메인 데이터 + end-to-end 학습 | 단순 태스크가 새 환경으로 일반화 | 대개 1분 미만의 단순 태스크이고 성공률도 낮음 |
| VLA (웹 사전학습 VLM 기반) | 언어 추종, 복잡한 조작 | 학습 분포와 가까운 환경에서만 평가됨 |

**정리하면, 단순 스킬은 데이터 다양성만으로 일반화되지만 장기·다단계 태스크를 새 환경에서 해낸 사례는 없었습니다.** 주방 정리처럼 상황의 조합이 폭발하는 태스크는 로봇 데이터를 무작정 늘려서 덮을 수 없습니다.

### 1.3 그래서 논문이 던지는 질문

> 하나의 학습 레시피로 ⓐ·ⓑ·ⓒ 세 층위의 일반화를 동시에 얻으려면, 무엇을 어떻게 학습시켜야 할까?

논문의 가설은 사람의 학습에서 출발합니다. 사람도 모든 것을 직접 연습해서 배우지는 않습니다. 남에게 들은 사실, 책에서 읽은 지식, 다른 맥락에서 해 본 경험을 목표 영역의 직접 경험과 섞어 씁니다. 로봇도 마찬가지로 **여러 출처의 지식을 이전받아야 한다**는 것입니다.

이 가설을 실행에 옮기려면 세 개의 벽을 넘어야 합니다.

**⛔ 벽 1 — 타깃 데이터의 커버리지.** 목표 플랫폼인 모바일 매니퓰레이터로 직접 모은 데이터는 약 400시간, 약 100개 가정 규모입니다. 중간 크기라고는 해도 새 집에서 벌어질 경우의 수를 덮기에는 턱없이 작습니다. 그리고 1.2절에서 보았듯 무작정 늘리는 것은 답이 아닙니다.

**⛔ 벽 2 — 지식원의 이질성.** 도움이 될 지식원들은 형식이 제각각입니다. 다른 embodiment의 액션, 웹의 캡션·VQA·bbox, 사람이 붙인 서브태스크 라벨, 사람의 음성 지시가 있습니다. 출력 공간도, 로봇의 자유도도, 다루는 추상 수준도 다릅니다. 논문 스스로 이 이질성을 가장 큰 장애물로 꼽았습니다.

**⛔ 벽 3 — 액션 표현의 딜레마.** 액션을 이산 토큰으로 쓰는 방식이 학습은 빠르지만 추론이 느리다면, 연속값으로 쓰는 방식은 실시간 추론에는 맞지만 학습이 느립니다. 50Hz로 움직여야 하는 로봇에게는 둘 다 절반의 답입니다.

벽 1과 2는 직관적입니다. 벽 3은 VLA가 액션을 어떻게 다루는지 알아야 정체가 보이므로, 2절에서 그 배경을 정리합니다.

## 2. 배경 — VLA는 액션을 어떻게 "말하는가"

### 2.1 VLA = 관측·지시 조건부 액션 청크의 가능도 최대화

VLA는 다양한 로봇 시연 데이터 위에서 모방학습으로 훈련됩니다. 목적함수는 관측과 지시가 주어졌을 때 액션의 로그가능도를 최대화하는 것입니다.

$$\max_\theta\ \mathbb{E}_{(\mathbf a_{t:t+H},\ \mathbf o_t,\ \ell)\sim\mathcal D}\Big[\log\pi_\theta\big(\mathbf a_{t:t+H}\mid\mathbf o_t,\ \ell\big)\Big]$$

- $\mathcal D$: 로봇 시연 데이터셋
- $\mathbf a_{t:t+H}$: **액션 청크**. 한 시점의 액션 하나가 아닌 여러 시점의 액션 묶음을 한 번에 예측합니다. π₀.₅의 청크는 50스텝이고 제어가 50Hz이므로 약 1초 분량입니다
- $\mathbf o_t=[\mathbf I^1_t,\dots,\mathbf I^n_t,\ \mathbf q_t]$: 카메라 이미지 $n$장과 proprioceptive state $\mathbf q_t$(관절각, 그리퍼 pose, 토르소 리프트, 베이스 속도)
- $\ell$: 자연어 태스크 지시
- $\pi_\theta$: 파라미터 $\theta$를 가진 정책

LLM 관점에서 보면 SFT와 같은 형태입니다. 프롬프트가 "관측+지시"이고 응답이 "액션"입니다. VLA는 관측·지시·액션을 모두 토큰으로 만들어 next-token prediction 문제로 바꾸고, 현대 LLM의 학습 도구를 그대로 가져다 씁니다.

이미지와 텍스트는 VLM의 토크나이저를 그대로 쓰면 됩니다. 남는 질문은 **연속값인 액션을 어떻게 토큰으로 만드느냐**이고, 답은 크게 두 갈래입니다.

### 2.2 이산 표현 — FAST

FAST는 액션 청크를 JPEG처럼 주파수 영역에서 압축한 뒤 BPE로 토큰화합니다.

```
 action chunk (50 x d)  ->  DCT per dimension  ->  quantize  ->  BPE  ->  discrete tokens
```

- 로봇 궤적은 매끄러워서 정보가 저주파 DCT 계수에 몰리므로, "스텝×차원마다 토큰 1개"로 나이브하게 binning할 때(예: 50×18 = 900개)보다 훨씬 짧고 덜 중복된 토큰열이 됩니다.
- 이렇게 만든 액션 토큰은 텍스트 토큰과 똑같이 cross-entropy로 학습됩니다.
- 세부 설계는 FAST 논문(Pertsch et al., 2025)의 것이고, π₀.₅ 본문은 이를 인용해 사용합니다.

### 2.3 연속 표현 — flow matching과 action expert

π₀는 액션을 flow matching으로 생성합니다. 정답 액션 청크와 가우시안 노이즈를 직선으로 보간하고, 그 직선의 방향(속도장)을 회귀합니다.

$$\mathbf a^{\tau,\omega}_{t:t+H}=\tau\,\mathbf a_{t:t+H}+(1-\tau)\,\omega,\qquad\omega\sim\mathcal N(0,\mathbf I),\quad\tau\in[0,1]$$

$$\mathcal L_{\text{flow}}(\theta)=\mathbb E_{\tau,\omega}\Big[\big\|\,(\omega-\mathbf a_{t:t+H})-f^a_\theta(\mathbf a^{\tau,\omega}_{t:t+H},\ \mathbf o_t,\ \ell)\,\big\|^2\Big]$$

- $\tau$: flow 시간 인덱스. 노이즈와 정답 사이의 보간 비율입니다
- $\omega$: 가우시안 노이즈
- $\mathbf a^{\tau,\omega}_{t:t+H}$: 노이즈가 섞인 중간 액션 청크
- $f^a_\theta$: 네트워크가 예측하는 속도장(vector field)
- $\omega-\mathbf a_{t:t+H}$: 회귀 목표. 노이즈와 정답을 잇는 직선의 방향

추론 때는 노이즈에서 출발해 학습된 속도장을 10번 적분하면 액션 청크가 나옵니다. diffusion 배경에서 보면 Rectified Flow·SD3와 같은 **직선 보간 경로 + 속도 회귀**입니다.

π₀는 이 속도장을 **action expert**라는 별도 가중치로 계산합니다. 액션 토큰은 VLM 백본과 같은 트랜스포머 안에서 처리되지만 다른 가중치 세트를 쓰며, 논문은 이를 mixture-of-experts에 비유하였습니다. action expert는 flow 기반 액션 생성에 특화되고, 백본보다 훨씬 작게 만들 수 있습니다.

둘 중 하나를 고르면 된다는 반론이 가능합니다. 실제로 π₀는 flow를, π₀-FAST는 이산 토큰을 골랐습니다. 문제는 두 표현의 장단점이 **정확히 엇갈린다**는 데 있습니다.

> ### 💡 이산 표현은 배우기에, 연속 표현은 움직이기에 좋다
>
> | | FAST (이산) | Flow (연속) |
> |---|---|---|
> | 학습 목적 | cross-entropy (VLM 사전학습과 같은 형태) | 속도장 MSE (새로운 목적) |
> | 학습 효율 | 빠름 | 느림 |
> | 추론 방식 | 자기회귀 디코딩 (토큰 수만큼 순차 forward) | 10-step 적분 (청크 전체를 병렬 생성, 작은 expert만 반복) |
> | 출력 정밀도 | 양자화 오차 있음 | 연속값 |
> | 실시간 제어 | 부적합 | 적합 |
>
> 논문이 FAST 논문을 인용해 밝히는 사실은 두 가지입니다. 이산 토큰으로 표현하면 VLA 학습이 훨씬 빨라집니다. 다만 자기회귀 디코딩 비용 때문에 실시간 추론에는 맞지 않습니다.
>
> 학습이 빠른 이유를 논문이 직접 분석하지는 않지만, 다음과 같이 해석할 수 있습니다. 이산 토큰에서 액션이 VLM에게 "또 하나의 언어"가 되어 사전학습된 출력층과 표현을 그대로 재사용한다면, flow에서는 무작위로 초기화된 모듈이 새로운 공간의 회귀 목표를 처음부터 배워야 합니다.
>
> 50Hz로 18~19차원을 제어해야 하는 모바일 매니퓰레이터에서 이 엇갈림은 피할 수 없는 **벽 3**이 됩니다. π₀.₅가 이것을 어떻게 푸는지는 3.3절에서 살펴봅니다.

## 3. 방법

π₀.₅의 아키텍처는 π₀와 거의 같습니다. 바뀐 것은 **무엇을 출력하는가**(서브태스크 텍스트), **무엇으로 학습하는가**(데이터 믹스처), **학습 단계마다 어떤 액션 표현을 쓰는가**(이산에서 연속으로 전환)입니다. 전체 흐름은 다음과 같습니다.

```
 init        : PaliGemma VLM (web-pretrained)
                 |
                 v
 PRE-TRAIN   : 280k steps, alpha = 0
               data = MM + ME + CE + HL + WD
               out  = text / bbox / subtask / FAST action tokens
                 |
                 v
 POST-TRAIN  : 80k steps, alpha = 10, + action expert (random init)
               data = MM + ME (filtered) + HL + WD + VI
               out  = text tokens + flow-matching action chunk
                 |
                 v
 INFERENCE   : subtask text (AR decode) -> 10 flow steps -> action chunk
```

- **pre-train** — 모든 출력을 이산 토큰으로 학습합니다. 액션도 FAST 토큰입니다.
- **post-train** — action expert를 붙이고 모바일 조작에 특화합니다.
- **inference** — 서브태스크를 먼저 텍스트로 내고, 그것을 조건으로 연속 액션을 냅니다.

데이터 약어(MM, ME, CE, HL, WD, VI)와 $\alpha$의 의미는 3.3~3.5절에서 차례로 정의합니다.

### 3.1 한 모델, 두 층위 — 계층적 분해

π₀.₅가 표현하는 것은 액션 청크와 텍스트 출력의 결합분포입니다. 논문은 이를 두 조건부 분포의 곱으로 분해하였습니다.

$$\pi_\theta\big(\mathbf a_{t:t+H},\ \hat\ell\mid\mathbf o_t,\ \ell\big)=\underbrace{\pi_\theta\big(\mathbf a_{t:t+H}\mid\mathbf o_t,\ \hat\ell\big)}_{\text{low-level}}\ \underbrace{\pi_\theta\big(\hat\ell\mid\mathbf o_t,\ \ell\big)}_{\text{high-level}}$$

- $\ell$: 전체 태스크 프롬프트 (예: "put away the dishes")
- $\hat\ell$: 모델이 내는 텍스트. 서브태스크(예: "pick up the plate")일 수도 있고, 웹 데이터 VQA의 답일 수도 있습니다
- **상위 추론** $\pi_\theta(\hat\ell\mid\mathbf o_t,\ell)$ — 관측과 전체 명령으로부터 다음 서브태스크를 텍스트로 생성합니다
- **저수준 추론** $\pi_\theta(\mathbf a\mid\mathbf o_t,\hat\ell)$ — 서브태스크를 조건으로 액션 청크를 생성합니다
- 두 분포 모두 **같은 가중치 $\theta$** 로 표현됩니다

LLM의 chain-of-thought와 같은 구조입니다. 먼저 "생각"(서브태스크)을 텍스트로 내고, 그 생각을 조건으로 "답"(액션)을 냅니다. 다만 매 스텝 추론 체인을 생성하는 embodied CoT 계열과 달리, π₀.₅의 상위 추론은 저수준 추론보다 낮은 주파수로 돕니다. 정확히 어떤 주기로 서브태스크를 다시 추론하는지는 논문에 명시되어 있지 않습니다.

상위 데이터에는 서브태스크 외에 관련 물체의 **bbox**도 라벨링되어 있고, 모델은 서브태스크를 내기 **전에** bbox를 먼저 예측하도록 학습됩니다. 어디에 무엇이 있는지 먼저 짚고 나서 다음 행동을 정하는 짧은 grounding 단계입니다.

여기서 눈여겨볼 설계가 하나 있습니다. 분해식에서 저수준 분포 $\pi_\theta(\mathbf a\mid\mathbf o_t,\hat\ell)$는 **원래 명령 $\ell$을 받지 않습니다.** "clean the kitchen"이라는 큰 그림을 모른 채 "pick up the plate"만 보고 움직인다는 뜻입니다. 정보를 일부러 버리는 이 설계가 이득인 이유는 다음과 같습니다.

> ### 💡 서브태스크 문자열은 두 층위를 잇는 인터페이스다
>
> $\ell$을 끊어내면 두 층위는 **짧은 자연어 명령 하나**로만 연결됩니다. 이 좁은 인터페이스가 세 가지를 가능하게 합니다.
>
> **⓵ 저수준 — 스킬 단위의 이전.** 저수준이 배우는 것은 "짧고 구체적인 명령 → 동작" 매핑뿐입니다. 논문은 여러 서브태스크로 이뤄진 로봇 데이터(MM·ME·CE)에 전부 서브태스크 라벨을 붙였습니다. 이 덕분에 실험실에서 모은 접시 옮기기 데이터와 가정 주방의 "pick up the plate"가 같은 명령 어휘 안에서 만납니다. 전체 태스크가 달라도 스킬은 이전됩니다.
>
> **⓶ 상위 — 순수 텍스트 생성.** 상위 추론은 이미지에서 텍스트를 내는 문제이므로, 웹의 VQA·캡션·bbox 지식이 그대로 쓰입니다.
>
> **⓷ 사람이 끼어들 자리.** 같은 인터페이스에 사람이 명령을 넣을 수 있습니다. 3.5절의 음성 지시 데이터 수집과 5.5절의 사람 oracle 비교가 모두 이 자리를 씁니다.
>
> **즉 $\ell$을 끊어낸 설계가 벽 2(이질성)의 구조적 해법입니다.** 모든 지식원이 모든 것을 가르칠 필요 없이, 각자 맞는 층위에만 기여하면 됩니다. agentic AI로 보면 planner와 executor를 한 모델에 넣고, 서브태스크 문자열을 tool call처럼 쓰는 구조입니다.

### 3.2 아키텍처 — 토큰 타입별 가중치와 attention mask

모델은 멀티모달 토큰 $N$개를 받아 멀티모달 출력 $N$개를 내는 트랜스포머입니다.

$$y_{1:N}=f\big(x_{1:N},\ A(x_{1:N}),\ \rho(x_{1:N})\big)$$

| 기호 | 의미 |
|---|---|
| $x_i$ | 입력 토큰. 텍스트 $x^w_i\in\mathbb N$, 이미지 패치 $x^I_i\in\mathbb R^{p\times p\times 3}$, 노이즈 섞인 액션 $x^a_i\in\mathbb R^d$ 중 하나 |
| $A(x_{1:N})\in[0,1]^{N\times N}$ | attention mask. 어떤 토큰이 어떤 토큰을 볼 수 있는지 정함 |
| $\rho(x_i)$ | 토큰 타입. 어떤 인코더와 **어떤 expert 가중치**로 처리할지 결정함 |
| $y^\ell_{1:M}$ | 텍스트 logit $M$개. 서브태스크, VQA 답, FAST 액션 토큰을 여기서 샘플링함 |
| $y^a_{1:H}$ | action expert 출력 $H$개. 선형 사영을 거쳐 속도장이 됨 |

$M+H\le N$입니다. 이미지·프롬프트 위치의 출력처럼 손실이 걸리지 않는 출력도 있습니다. 구성 요소는 다음과 같습니다(부록 E).

| 구성 | 사양 | 비고 |
|---|---|---|
| 비전 인코더 | SigLIP, 400M | PaliGemma에서 초기화 |
| VLM 백본 | Gemma 2B (width 2048, depth 18, MLP 16,384) | PaliGemma에서 초기화 |
| action expert | 300M (width 1024, MLP 4096, 나머지는 백본과 동일) | post-training 시작 시 무작위 초기화 |
| timestep 주입 | sinusoidal 인코딩 → swish MLP → adaptive RMSNorm으로 각 층에 주입 | π₀는 $\tau$를 노이즈 액션과 결합해 입력함 |
| proprioception | 이산화해 텍스트 토큰으로 prefix에 넣음 | |

diffusion 배경에서 보면 익숙한 조합입니다.

- **MM-DiT와 닮은 구조** — 토큰 타입마다 가중치를 따로 두고, attention만 한 시퀀스에서 함께 계산합니다. SD3의 MM-DiT(모달리티별 가중치 + joint attention)와 같은 발상입니다. 차이는 mask에 있습니다. MM-DiT의 joint attention이 완전 양방향이라면, π₀.₅는 아래와 같은 block mask를 겁니다.
- **DiT와 같은 timestep 컨디셔닝** — adaptive RMSNorm은 DiT의 adaLN과 같은 방식으로 timestep을 각 층에 주입합니다.

| query ↓ · key → | prefix (이미지·프롬프트·state) | FAST 토큰 | expert 토큰 |
|---|---|---|---|
| **prefix** | 양방향 | ✗ | ✗ |
| **FAST 토큰** | ✓ | causal | ✗ |
| **expert 토큰** | ✓ | ✗ | 양방향 |

- prefix(이미지, 프롬프트, state)는 서로 양방향으로 봅니다.
- FAST 토큰은 prefix와 자기 앞의 FAST 토큰만 봅니다. 즉 자기회귀입니다.
- expert 토큰은 prefix와 다른 expert 토큰만 보고, FAST 토큰은 보지 않습니다.
- prefix는 expert를 절대 보지 않습니다. 정보는 **VLM → expert 한 방향**으로만 흐릅니다.

**FAST와 expert 사이를 서로 막는 이유는 정보 누설입니다.** 학습 중 FAST 토큰은 teacher forcing으로 입력되는 **정답 액션**입니다. expert가 이것을 볼 수 있다면 관측에서 액션을 생성하는 법 대신 정답을 베끼는 법을 배웁니다. 게다가 추론 때는 FAST 토큰을 생성하지도 않습니다.

이 마스크를 보면 안심이 되기 쉽습니다. VLM 쪽 토큰은 action expert를 절대 보지 않으니, post-training에서 무작위 초기화된 expert를 붙여도 VLM의 사전학습 지식은 안전해 보입니다.

> ### 💡 순전파는 단방향이지만, 역전파는 단방향이 아니다
>
> expert 토큰의 attention을 풀어 쓰면 gradient가 흐르는 경로가 드러납니다.
>
> $$\mathrm{attn}_a=\operatorname{softmax}\!\Big(\tfrac{1}{\sqrt{d_h}}\,Q_a(X_a)\,\big[K_b(X_b);\ K_a(X_a)\big]^{\top}\Big)\,\big[V_b(X_b);\ V_a(X_a)\big]$$
>
> - $X_b$, $X_a$: 백본 가중치로 처리되는 토큰, expert 가중치로 처리되는 토큰
> - $Q, K, V$: 각 가중치 세트의 query·key·value projection
> - $[\,\cdot\,;\,\cdot\,]$: 토큰 축 방향으로 이어붙이기
> - $d_h$: attention head 차원
>
> **순전파** — 백본 토큰의 attention에는 $K_a, V_a$가 들어가지 않으므로, VLM 쪽 activation은 expert가 있든 없든 똑같습니다.
>
> **역전파** — expert의 출력은 $K_b(X_b)$와 $V_b(X_b)$에 의존하므로, flow 손실의 gradient가 이 항을 거쳐 백본 가중치까지 흘러갑니다.
>
> $$\frac{\partial\mathcal L_{\text{flow}}}{\partial\theta_{\text{VLM}}}\ \neq\ 0$$
>
> π₀.₅ 본문은 stop-gradient를 언급하지 않습니다. 대신 post-training에서 next-token 예측과 웹 데이터를 함께 학습시켜 백본의 텍스트 능력을 **보존**한다고만 밝혔습니다. 무작위 expert의 gradient가 사전학습 지식을 실제로 얼마나 해치는지는 후속 연구가 정면으로 다루며, 6절에서 다시 살펴봅니다.

### 3.3 이산과 연속을 한 손실로 — 벽 3을 뚫는 장치

π₀.₅는 두 액션 표현을 하나의 손실에 함께 넣습니다.

$$\mathcal L(\theta)=\mathbb E_{\mathcal D,\tau,\omega}\Big[\ \mathrm{CE}\big(x_{1:M},\ f^\ell_\theta(\mathbf o_t,\ell)\big)\ +\ \alpha\,\big\|\,\omega-\mathbf a_{t:t+H}-f^a_\theta(\mathbf a^{\tau,\omega}_{t:t+H},\ \mathbf o_t,\ \ell)\big\|^2\ \Big]\qquad(1)$$

| 기호 | 의미 |
|---|---|
| $\mathrm{CE}(\cdot)$ | 텍스트 토큰과 예측 logit 사이의 cross-entropy. **FAST 액션 토큰도 여기에 포함**됨 (논문 표기는 $H$) |
| $x_{1:M}$ | 정답 텍스트 토큰열 |
| $f^\ell_\theta$ | VLM의 텍스트 logit 출력 |
| $f^a_\theta$ | action expert의 속도장 출력 |
| $\alpha$ | 두 항의 trade-off 가중치 |

학습 단계에 따라 $\alpha$가 바뀌면서 모델의 성격이 바뀝니다.

| 단계 | $\alpha$ | 학습되는 것 | 의미 |
|---|---|---|---|
| pre-train (280k step) | 0 | CE만 (텍스트, bbox, 서브태스크, FAST 액션) | 액션을 텍스트 토큰으로 다루는 평범한 VLM 학습 |
| post-train (80k step) | 10 | CE(FAST 포함) + flow | expert를 붙이고 두 액션 표현을 동시에 학습. 서로는 mask로 차단 |
| inference | — | — | 서브태스크만 자기회귀 디코딩, 액션은 expert의 10-step 적분. FAST 토큰은 쓰지 않음 |

**2절에서 예고한 벽 3에 π₀.₅가 내놓은 답은, 둘 중 하나를 고르지 않고 배울 때는 이산 표현을, 움직일 때는 연속 표현을 쓰는 것입니다.** 논문은 이 절차가 안정적인 사전학습과 뛰어난 언어 추종 능력으로 이어진다고 보고하였습니다.

flow timestep은 π₀를 따라 균등분포가 아닌 분포에서 샘플합니다. 구체적으로 $p(\tau)=\mathrm{Beta}\big(\tfrac{s-\tau}{s};\,1.5,\,1\big)$이고, $s=0.999$는 샘플링하는 $\tau$의 상한입니다. 이 분포는 낮은 $\tau$를 강조합니다.

그런데 식 (1)과 부록의 flow 표기를 그대로 구현하려 하면 걸리는 지점이 몇 가지 있습니다.

> ### ⚠️ 팩트체크 — 구현할 때 걸릴 수 있는 표기 비일관
>
> | 위치 | 내용 |
> |---|---|
> | flow 목표의 부호 | 보간식 $\tau\mathbf a+(1-\tau)\omega$를 $\tau$로 미분하면 $\mathbf a-\omega$인데, 회귀 목표는 $\omega-\mathbf a$로 적혀 있음. 이 부호는 $\tau=1$을 노이즈 쪽에 두는 규약일 때 자연스러움. 적분 방향은 본문에 없고, "낮은 $\tau$ 강조"가 노이즈 쪽 강조인지 데이터 쪽 강조인지도 이 규약에 따라 뒤집힘 |
> | 기호 중복 | $H$가 cross-entropy와 horizon에, $\alpha$가 손실 가중치와 Beta 파라미터에 함께 쓰임. 부록은 horizon 50을 "$H=49$"로 적는데, $t{:}t{+}H$가 양 끝을 포함하는 색인이기 때문임 |
> | 식 (1)의 조건 | 분해식에서 저수준은 $\hat\ell$에 조건부인데, 식 (1)의 flow 항은 $\ell$에 조건부로 적혀 있음. "prefix에 들어 있는 프롬프트"라는 뜻으로 느슨하게 읽어야 함 |
> | head 수 | 부록의 백본 설정 num_heads=18은 18×256=4608로 width 2048과 맞지 않고, 원래 Gemma 2B 설정(8 heads)과도 다름. 오기일 가능성이 있음 |

### 3.4 사전학습 데이터 — 벽 1·2를 넘는 재료

사전학습은 280k step 동안 다음 데이터를 섞어 진행합니다. post-training 열은 3.5절을 미리 반영한 것입니다.

| 약어 | 내용 | 공급하는 것 | post-train |
|---|---|---|---|
| **MM** (Mobile Manipulator) | 모바일 매니퓰레이터, 약 400시간, 약 100개 가정 | 타깃 embodiment와 타깃 태스크 | ✅ (성공·길이 필터) |
| **ME** (Multi-Environment) | 고정형 1~2팔 로봇, 다양한 가정 | 환경 다양성. 가볍고 옮기기 쉬워 더 많은 집에서 수집 가능 | ✅ (필터) |
| **CE** (Cross-Embodiment) | 실험실 탁상 환경, 여러 로봇 타입, OXE 포함 | 태스크 다양성. 평가와 관련된 태스크와 무관한 태스크가 섞여 있음 | ❌ 제외 |
| **HL** (High-Level) | 다단계 로봇 데이터의 서브태스크 수동 라벨 + 관련 물체 bbox | 서브태스크 추론, grounding | ✅ (다중 환경 데이터 slice) |
| **WD** (Web Data) | 캡션(CapsFusion, COCO), VQA(Cambrian-7M, PixMo, VQAv2), 물체 localization(+실내·가정용품 bbox 추가) | 의미 지식, 물체 개념 | ✅ (능력 보존용) |
| **VI** (Verbal Instruction) | 사람이 학습된 저수준 정책을 언어로 단계별 지휘 | 좋은 상위 명령의 시연 | post-train에서 신규 |

첫 학습 단계에서 쓰인 학습 예시의 **97.6%** 는 가정에서 일하는 모바일 매니퓰레이터가 아닌 다른 로봇이나 웹 같은 다른 출처에서 옵니다(Introduction). 타깃 데이터가 2.4%에 불과한 믹스처입니다.

서로 다른 로봇과 과제를 하나의 토큰 공간에 넣는 장치는 단순합니다.

- **정규화** — 데이터셋마다 액션 차원별 1%·99% 분위수로 $[-1,1]$ 범위에 맞춥니다.
- **차원 통일** — 가장 큰 액션 공간에 맞춰 차원을 고정하고, 저차원 로봇은 zero-pad합니다.
- **제어 모드 태그** — 목표가 관절 pose인지 end-effector pose인지를 프롬프트의 `<control_mode>` 토큰으로 구분합니다.
- **bbox도 텍스트** — 위치를 `<loc0112>` 같은 location 토큰으로 표현합니다.

결국 "모든 것을 토큰으로" 만드는 전략이며, 멀티모달 LLM의 instruction-tuning 믹스처를 짜는 방식과 같습니다. **정리하면, 벽 1은 타깃 데이터를 늘리는 대신 다른 출처로 우회해서 넘고, 벽 2는 모든 지식원을 한 시퀀스 형식에 태워서 넘습니다.**

### 3.5 Post-training — 특화, expert 부착, 그리고 VI

사전학습 뒤 $\alpha=10$으로 80k step을 추가 학습합니다. 이 단계의 목적은 두 가지입니다. 하나는 모델을 가정 내 모바일 조작에 특화하는 것이고, 다른 하나는 flow matching으로 연속 액션 청크를 내는 action expert를 붙이는 것입니다.

- **액션 데이터** — MM·ME를 성공했고 일정 길이 이하인 에피소드로 걸러 씁니다.
- **CE 제외** — 실험실 데이터는 빼서 모바일 조작과 다양한 환경에 집중합니다.
- **WD 유지** — 의미·시각 능력을 보존하기 위해 계속 섞습니다.
- **VI 추가** — 전문가가 학습된 저수준 정책을 실시간으로 "언어로 원격조종"하면서, 적절한 서브태스크 명령을 단계별로 고릅니다. 이렇게 모은 것이 학습된 정책을 위한 좋은 상위 출력의 시연이 됩니다.

3.1절에서 말한 "사람이 끼어들 자리"를 데이터 수집에 쓴 것이 VI입니다. 그런데 MM·ME 데이터에는 이미 사람이 붙인 서브태스크 라벨(HL)이 있습니다. 그럼에도 VI를 따로 모은 이유는 다음과 같습니다.

> ### 💡 VI는 상위 정책을 위한 on-policy 데이터다
>
> 논문이 "on-policy"라는 말을 쓰지는 않지만, 두 데이터의 차이를 보면 이렇게 읽힙니다. 두 데이터를 가르는 것은 **어떤 상태에 라벨이 붙었는가**입니다.
>
> | | HL 라벨 | VI |
> |---|---|---|
> | 만드는 방식 | 사람의 teleop 시연에 사후 라벨링 | 학습된 저수준 정책을 돌리며 사람이 실시간으로 명령 선택 |
> | 라벨이 붙은 상태 | **전문가 조종자**가 방문한 상태 | **실제 배포될 시스템**이 방문한 상태 |
> | 가르치는 것 | 전문가가 무엇을 했는가 | 이 저수준 정책에게 지금 무엇을 시켜야 통하는가 |
>
> 배포 시 상위 정책이 명령을 내리는 대상은 전문가가 아닌 **학습된 저수준 정책**입니다. 이 정책은 전문가와 다르게 삐끗하고 다르게 드리프트하므로, 상위 정책은 그 정책이 만드는 상태에서 그 정책이 실제로 수행할 수 있는 명령을 골라야 합니다. 이것은 상위 층위에서 생기는 공변량 이동(covariate shift) 문제이고, VI는 배포될 시스템이 실제로 방문하는 상태에 라벨을 붙여 이 틈을 메웁니다.
>
> **VI는 모바일 조작 상위 예시의 약 11%에 불과하지만, 빼면 성능이 유의하게 떨어질 만큼 효과가 큽니다(5.5절, Fig. 13).** agentic AI로 옮기면, planner를 이상적인 가상 trace가 아닌 **실제 배포될 executor를 루프에 넣고 수집한 trace**로 학습시키는 것과 같습니다.
>
> 참고로 Fig. 4의 예시에는 "Policy: put plate in sink / Relabeled: put plate on rack" 같은 쌍이 보입니다. 명령과 실제 수행이 어긋난 경우를 사후에 다시 라벨링한 것으로 보이지만, 본문에는 이 relabeling 절차가 설명되어 있지 않습니다.

### 3.6 추론과 제어

```
 prompt l  ("clean the kitchen")
   |
   v
 4 cams + q_t  -->  VLM  --AR decode-->  l_hat  ("pick up the plate")
                     |
                     |  prefix = wrist + front cams, l_hat, q_t
                     v
 noise  -->  action expert (10 flow steps)  -->  action chunk (50 steps)
                                                    |
                                                    v
                                         PD controllers @ 50 Hz
```

- **카메라** — 상위 추론은 전방·후방·양 손목 카메라 4대를 모두 쓰고, 저수준 추론은 손목 2대와 전방 카메라만 씁니다.
- **출력** — 팔·그리퍼·토르소 리프트의 목표 pose와 베이스의 목표 속도를 50Hz로 직접 명령합니다(action chunking).
- **제어기** — 목표값은 단순 PD 제어기가 추종합니다. 추가적인 궤적 계획이나 충돌 검사는 없으며, 조작과 내비게이션이 모두 end-to-end입니다.

상태·액션 공간의 차원은 로봇 구성에서 바로 나옵니다.

$$\underbrace{2\times(6+1)}_{\text{양팔+그리퍼}}\ +\ \underbrace{3}_{\text{베이스 } (v_x,\,v_y,\,\omega)}\ +\ \underbrace{1\sim 2}_{\text{리프트}}\ =\ 18\sim 19$$

- 팔은 6 DoF, 그리퍼는 1 DoF입니다
- 홀로노믹 베이스는 선속도 2축과 각속도 1축으로 제어됩니다
- 토르소 리프트는 플랫폼에 따라 상하 1축 또는 상하·전후 2축입니다

## 4. 왜 작동하는가 — 세 벽의 회수

1.3절에서 명명한 세 벽이 어디서 넘어졌는지 먼저 정리합니다.

| 벽 | π₀.₅의 해법 | 절 |
|---|---|---|
| ⛔ 벽 1 — 커버리지 | 타깃 데이터를 늘리지 않고, 가벼운 고정팔(ME)로 더 많은 집을, 실험실(CE)로 더 많은 태스크를, 웹(WD)으로 물체 개념을 채움 | 3.4절 |
| ⛔ 벽 2 — 이질성 | 서브태스크 인터페이스로 층위를 분리하고, 모든 지식원을 토큰 시퀀스로 통일함 | 3.1절, 3.4절 |
| ⛔ 벽 3 — 표현 | 이산으로 배우고 연속으로 움직이는 2단계 전환 | 3.3절 |

**이것을 1.1절의 세 층위에 맞춰 보면, 지식원마다 먹이는 층위가 다르다는 논문의 주장이 실험과 대응됩니다.**

| 일반화 층위 | 주 공급원 | 근거 실험 |
|---|---|---|
| ⓐ 스킬 | MM·ME(환경 다양성), CE(태스크 다양성) | 환경 수 스케일링(Fig. 8), no ME / no CE(Fig. 10) |
| ⓑ 조합 | HL 서브태스크 예측, VI | no HL / no VI / implicit HL(Fig. 13) |
| ⓒ 의미 | WD | no WD → OOD 물체 언어 추종 하락(Fig. 11), 상위 추론 성능 하락(Fig. 13) |

여기서 한 가지 의문이 남습니다. 상위 추론의 이득이 추론할 때 서브태스크를 실제로 말하는 데서 오는지, 아니면 그렇게 말하도록 학습하는 과정에서 오는지입니다.

> ### 💡 서브태스크를 말하지 않아도, 말하는 법을 배운 것만으로 좋아진다
>
> 5.5절의 상위 추론 비교에서 2위는 **implicit HL**입니다. 추론할 때는 서브태스크를 전혀 생성하지 않고 전체 명령을 바로 저수준에 넣지만, 학습 믹스처에는 서브태스크 예측 데이터(HL)가 들어 있는 변형입니다. 이 변형은 HL 데이터 자체를 뺀 no HL보다 유의하게 낫습니다.
>
> 논문은 명시적인 서브태스크 추론에도 이득이 있지만, 그 이득의 상당 부분은 서브태스크 **예측** 데이터를 학습 믹스처에 넣는 것만으로 이미 얻어진다고 해석하였습니다. 서브태스크 예측이 보조 과제로서 표현 자체를 태스크 구조에 맞게 빚는다는 뜻입니다.
>
> LLM에서 CoT 데이터로 학습하면 CoT 없이 바로 답할 때도 성능이 오르는 현상과 닮았습니다. 다만 같은 메커니즘이라는 증거는 논문에 없으므로, 유비로만 읽어야 합니다.

또 하나의 축은 **언어 추종**입니다. 부록 C의 비교(Fig. 15)에서 π₀.₅는 π₀-FAST+Flow보다 약간, π₀보다는 크게 높은 비율로 지시된 물체를 고릅니다. 논문은 이를 이산 토큰 학습이 언어 추종에 중요하다는 근거로 들었습니다. 2절의 💡에서 본 "이산 표현은 배우기에 좋다"는 성질과, 3.2절에서 본 역전파 간섭 문제를 다른 각도에서 본 결과입니다.

이렇게 보면 π₀.₅가 이전 모델과 무엇이 다른지가 분명해집니다.

> ### 📌 π₀.₅의 차별점은 모듈이 아니라 배치다
>
> **π₀.₅의 차별점은 어떤 지식을, 어느 층위에, 어느 학습 단계에서 먹이느냐에 있습니다.** π₀에 없던 새 네트워크 모듈은 거의 없습니다.
>
> | | 저수준 (액션) | 상위 (서브태스크) |
> |---|---|---|
> | pre-train | MM·ME·CE 액션을 FAST 토큰으로 | HL 라벨 + WD |
> | post-train | MM·ME 액션을 flow expert로 (FAST 병행) | HL + WD + **VI** |
>
> 타깃 데이터는 사전학습 예시의 2.4%에 불과합니다. 나머지 97.6%가 각자 맞는 칸에 들어가 일반화를 만듭니다.

## 5. 실험

### 5.0 평가 설정

모든 평가는 학습에 없던 환경에서 이뤄집니다. 통제된 비교는 mock 주방 3곳과 mock 침실 3곳에서, 최종 평가는 실제 가정 3곳의 주방과 침실에서 합니다(총 12개 장소). 표준 평가는 태스크 4개 × 10회로 정책당 40 에피소드이고, 유의성은 양측 t-검정으로 판단합니다. 로봇 고장이나 시간 제한 등으로 취소된 에피소드는 제외됩니다.

지표는 루브릭 부분점수(진척도 %)입니다(부록 B).

| 태스크 | 만점 | 채점 |
|---|---|---|
| Dishes in Sink | 8 | 식기 4개 각각 집기 +1, 싱크에 넣기 +1 |
| Items in Drawer | 4 | 집기, 서랍 열기, 넣기, 닫기 각 +1 |
| Laundry Basket | 3 | 이동해서 집기, 바구니에 올리기, 완전히 넣기 각 +1 |
| Make Bed | 5 | 이불 펴기, 베개 2개 각 +1, "매우 깔끔함" 보너스 +2 |

두 가지를 기억해 둘 필요가 있습니다. 지표는 이진 성공률이 아닌 **부분점수**입니다. 그리고 본문 결과는 모두 막대그래프로만 제시되므로, 이 글은 수치 대신 결과의 방향과 유의성만 옮깁니다.

### 5.1 실제 가정에서 일반화되는가 (Fig. 7)

학습에 없던 가정 3곳에서, 두 로봇 타입으로 items in drawer, laundry basket, dishes in sink를 각 10회씩 평가했습니다. 논문은 π₀.₅가 각 가정에서 다양한 태스크를 일관되게 수행했고, mock 환경 성능이 실제 가정 성능을 잘 대표했다고 보고하였습니다. 모델은 "place the dishes in the sink" 같은 단순한 명령만 받고, "pick up the cup" 같은 단계는 상위 추론이 스스로 정합니다.

그런데 이 결과를 서론의 주장과 나란히 놓으면 간극이 보입니다.

> ### ⚠️ 팩트체크 — "10~15분 장기 조작"은 정량 평가의 대상이 아니다
>
> Fig. 1과 서론은 주방이나 침실 전체를 치우는 10~15분 길이의 장기 조작을 내세웁니다. 그러나 정량 평가 태스크는 대부분 약 2~5분 길이이고, 지표도 이진 성공률이 아닌 부분점수입니다. 10~15분 규모의 방 전체 정리는 정성적 시연으로 제시될 뿐 수치로 뒷받침되지는 않습니다. 인용할 때 둘을 구분할 필요가 있습니다.

### 5.2 학습 환경 수에 따라 어떻게 스케일되는가 (Fig. 8, 9)

모바일 조작 데이터의 수집 장소 수를 3 → 12 → 22 → 53 → 82 → 104곳으로 늘려 가며 비교했습니다. 모든 모델이 40k step 동안 같은 수의 고유 샘플을 보도록 맞춰, 데이터 양의 효과를 통제했습니다.

- **태스크 진척도** — 장소 수와 함께 대체로 오릅니다. 104곳 모델은 **테스트 가정 데이터로 직접 학습한 대조군과 비슷한 수준**에 도달합니다.
- **co-training 없는 베이스라인** — 다른 공동학습 과제 없이 테스트 가정 데이터만, 또는 104곳 MM 데이터만으로 학습한 모델은 크게 뒤처집니다. 논문은 이를 두고, 테스트 가정의 로봇 데이터를 봤더라도 다른 지식원이 좋은 일반화에 필수라고 해석하였습니다.
- **언어 추종** — 물체 5개 중 지정된 하나를 옮기는 과제입니다. 목표 물체를 방해물보다 멀리 두어, 지시를 이해하지 못하는 정책은 약 20%만 맞히도록 설계했습니다(부록 C). 장소 수가 늘수록 두 지표가 모두 오르며, 학습 범주의 새 물체(ID)가 처음 보는 범주의 물체(OOD: 깔때기, 약병, 보안경 등)보다 빨리 오릅니다.

**다만 이 실험은 계산 비용 때문에 MM 없이 사전학습한 뒤 MM 양만 바꿔 post-train한 축소 레시피라는 점에 주의해야 합니다.** 전체 π₀.₅ 레시피의 스케일링 곡선이 아니며, 논문도 이를 명시하였습니다.

### 5.3 데이터 믹스처의 각 성분은 얼마나 중요한가 (Fig. 10, 11, 16)

| 제거한 성분 | mock 태스크 진척도 | 언어 추종 |
|---|---|---|
| no WD | **유의차 없음** | **OOD 물체에서 유의하게 하락** |
| no ME | 유의하게 하락 | ID·OOD 모두 하락 |
| no CE | 유의하게 하락 | ID·OOD 모두 하락 |
| no ME & CE | 가장 크게 하락 | 하락 |

태스크별로 나눠 보면(Fig. 16) 차이가 더 선명합니다.

- **Items in Drawer** — 폭넓은 일상 물체를 알아봐야 하는 태스크라서, ME·CE는 물론 WD를 빼도 떨어집니다.
- **Dishes in Sink** — WD를 빼도 견디지만 ME·CE를 빼면 떨어집니다. 일반적인 조작 전략이 핵심인 태스크입니다.
- **Laundry Basket, Make Bed** — cross-embodiment 데이터를 빼면 떨어지고, 다른 변화에는 덜 민감합니다.

**웹 데이터의 효용이 스킬(ⓐ)이 아닌 의미(ⓒ) 층위에 집중된다는 4절의 대응이 바로 이 결과에서 나옵니다.**

### 5.4 π₀와 비교하면 어떤가 (Fig. 12, 15)

| 모델 | 액션 학습 방식 | HL·WD 데이터 | 상위 추론 |
|---|---|---|---|
| π₀ | 처음부터 flow expert | ✗ | ✗ |
| π₀-FAST+Flow | 식 (1)의 하이브리드 | ✗ (액션 데이터만) | ✗ |
| **π₀.₅** | FAST 사전학습 → expert 부착 | ✓ | ✓ |

**π₀.₅는 두 모델을 모두 유의하게 이깁니다.** 세 모델은 같은 cross-embodiment 로봇 데이터로, 비슷한 step 수만큼 학습했습니다. π₀를 300k step까지 더 학습시켜도 결과는 유지되며, 논문은 이를 FAST 토큰 학습이 순수 diffusion 학습보다 계산 효율적이라는 근거로 들었습니다.

두 비교는 서로 다른 효과를 분리합니다.

- **π₀ vs π₀-FAST+Flow** — 같은 데이터에서 학습 방식(하이브리드)의 효과
- **π₀-FAST+Flow vs π₀.₅** — HL·WD 공동학습과 상위 추론의 효과 (두 요인이 함께 섞여 있음)

### 5.5 상위 추론은 얼마나 중요한가 (Fig. 13, 17)

저수준은 모두 π₀.₅로 고정하고, 상위 정책만 바꾼 변형을 비교합니다. 이 중 human HL은 3.1절의 인터페이스에 사람이 직접 명령을 넣는 변형이고, implicit HL은 4절에서 본 변형입니다.

| 변형 | 내용 | 결과 |
|---|---|---|
| **π₀.₅** | 같은 모델이 상위·저수준 모두 수행 | **1위** |
| implicit HL | 상위 추론은 하지 않지만 HL 데이터로는 학습 | **2위** |
| human HL | 전문가가 상위 명령을 입력하는 "oracle" | π₀.₅와 implicit HL보다 아래 |
| no HL | HL 데이터로 학습하지도 않음 | 유의하게 하락 |
| no VI | VI 데이터 제외 | 유의하게 하락 |
| no WD | 웹 데이터 제외 | 유의하게 하락 |
| GPT-4 | 태스크 설명과 자주 쓰는 라벨 목록을 주고 zero-shot 프롬프팅 | **최하위** |

no VI의 하락은 3.5절에서 VI를 on-policy 데이터로 읽은 해석을 뒷받침합니다. no WD의 하락은 웹 데이터의 효용이 상위 정책에 크게 쏠려 있음을 보여 줍니다. 그런데 순위를 다시 보면 이상한 점이 하나 있습니다.

> ### ⚠️ 팩트체크 — 상한이라던 사람 oracle이 상한이 아니다
>
> 논문은 human HL을 성능의 상한을 주는 oracle로 정의하였습니다. 그러나 full π₀.₅가 이를 이기고, 상위 추론을 아예 하지 않는 implicit HL이 2위를 차지합니다. 이 실험에서 oracle은 상한으로 기능하지 않으며, 논문은 그 이유를 분석하지 않았습니다.
>
> **가장 그럴듯한 설명은 인터페이스 정렬입니다.** 저수준 정책은 학습 라벨의 어휘·세분도·전환 타이밍에 맞춘 명령에 가장 잘 반응합니다. 사람의 즉석 명령은 그 분포에서 벗어날 수 있고, 반응 지연도 끼어듭니다. 라벨 목록을 받고도 최하위인 GPT-4도 같은 맥락으로 읽힙니다. 정리하면, 좋은 상위 정책의 조건은 planner의 똑똑함이 아닌 **이 executor와의 정렬**이라고 판단됩니다.

## 6. 위치잡기 — 이웃 연구들 속에서

논문의 Related Work가 세우는 계보는 넷입니다.

| 계보 | 대표 | π₀.₅가 짚는 한계 | π₀.₅의 위치 |
|---|---|---|---|
| generalist 정책·VLA | RT-2, OpenVLA, π₀ 등 | 학습 분포와 가까운 환경에서만 평가 | 완전히 새 집에서 평가 |
| 비로봇 데이터 co-training | RT-2, PaLM-E, Magma | VLM 학습용 데이터에 국한 | 다른 로봇, 서브태스크, 음성 지시까지 확장 |
| 언어 기반 계층 추론 | SayCan, YAY Robot, [Hi Robot](/notes/hirobot-hierarchical-vla/), HAMSTER / ECoT 계열 | 두 모델로 분리하거나, 추론이 매 스텝 돌아감 | 한 모델 + 저주파 상위 추론 |
| open-world 로봇 시스템 | Roomba, AnyGrasp, RUM, "On Bringing Robots Home" | 좁은 primitive, 또는 1분 미만 단순 태스크 | 다단계 장기 태스크 |

가장 가까운 연구는 계층 추론 계보입니다. 이 계보는 모델 구성 방식에 따라 두 갈래로 나뉘고, π₀.₅는 둘 사이의 조합을 택하였습니다.

| | 두 모델 계층 (SayCan, Hi Robot 등) | embodied CoT (ECoT 등) | **π₀.₅** |
|---|---|---|---|
| 모델 수 | 2 (VLM 플래너 + 저수준 정책) | 1 | 1 |
| 상위 추론 주기 | 저주파 | 저수준과 같은 주기 | 저주파 |
| 상위 정책의 학습 | 별도 학습, 또는 사전학습 LLM·VLM 활용 | 추론 체인 라벨 | 저수준과 공동학습 (HL + WD + VI) |

**논문 자신도 기여를 "co-training이라는 발상"이 아닌, 특정한 데이터 조합이 새 환경에서의 장기 행동을 가능하게 했다는 데서 찾았습니다.** 멀티태스크 학습과 co-training 자체는 새롭지 않다고 인정하였습니다.

3.2절에서는 역전파 경로를 짚으며 질문 하나를 남겼습니다. 무작위 expert의 gradient가 백본을 흔든다면 그 간섭이 실제로 얼마나 문제였는지가 그 질문입니다.

> ### 🔗 Knowledge Insulation (Driess et al., 2025-05) — 백본을 flow gradient로부터 격리하다
>
> 같은 팀의 후속 연구가 이 질문을 정면으로 다룹니다. 이 연구는 사전학습 백본에 새 flow/diffusion action expert를 나이브하게 붙이면 **학습 속도와 지식 이전이 모두 크게 손상된다**는 분석 결과를 보고하였고, 해법으로 expert가 백본을 참조하는 경로에 stop-gradient를 거는 방식을 제시하였습니다.
>
> $$\mathrm{attn}_a=\operatorname{softmax}\!\Big(\tfrac{1}{\sqrt{d_h}}\,Q_a\,\big[\operatorname{sg}(K_b);\ K_a\big]^{\top}\Big)\,\big[\operatorname{sg}(V_b);\ V_a\big]$$
>
> - $\operatorname{sg}(\cdot)$: stop-gradient. 순전파 값은 그대로 두고 역전파만 끊습니다
> - 나머지 기호는 3.2절의 식과 같습니다
>
> | | π₀.₅ 본문 | Knowledge Insulation |
> |---|---|---|
> | 백본 보호 방식 | next-token·웹 데이터 공동학습으로 보존 | expert에서 백본으로 가는 gradient를 stop-gradient로 차단 |
> | 학습 단계 | 2단계 (FAST 사전학습 → expert 부착) | 단일 단계에서 FAST와 expert를 동시에 학습 |
> | flow 손실 가중치 | $\alpha=10$ | $\alpha=1$로 충분 (flow 손실이 독립된 가중치에만 걸리므로) |
>
> **stop-gradient는 백본이 이산 액션도 함께 예측하도록 학습될 때에만 타당합니다.** 그래야 gradient를 끊어도 백본이 액션에 필요한 표현을 스스로 배웁니다. π₀.₅가 식 (1)에서 FAST 토큰 학습을 post-training까지 유지한 것이 바로 이 조건입니다. PI는 이 연구가 π₀.₅에서 쓴 방법을 정식화하고 단일 단계 레시피로 확장한 것이라고 설명하였습니다.
>
> 다만 π₀.₅ v1 자체가 stop-gradient를 썼는지는 본문만으로 판단할 수 없습니다. stop-gradient가 있으면 $\alpha=1$로 충분하다는 KI의 설명에 비추면, π₀.₅의 $\alpha=10$은 flow 손실이 공유 가중치에 영향을 주던 설정의 흔적일 수 있습니다(필자의 추론).

## 7. 한계

**논문이 인정한 한계**

- **환경별 난관** — 낯선 서랍 손잡이, 물리적으로 열기 어려운 캐비닛
- **부분 관측** — 로봇 팔이 닦아야 할 얼룩을 가리는 경우
- **상위 추론의 산만함** — 물건을 넣다가 서랍을 여러 번 여닫는 경우
- **단순한 프롬프트** — 처리할 수 있는 명령의 복잡도는 학습 라벨이 정합니다
- **짧은 컨텍스트, 메모리 없음** — 방 사이를 이동하거나 물건 위치를 기억해야 하는 태스크에 약합니다

**추가로 짚을 지점**

- **옮겨 간 사람 라벨링 비용** — 다단계 로봇 데이터 전체의 서브태스크 수동 라벨, bbox 라벨, VI 수집이 필요합니다. co-training이 비용을 없앴다기보다 teleop 비용을 annotation 비용으로 옮긴 측면이 있습니다. 논문도 합성 라벨링을 향후 과제로 들었습니다.
- **순수 모방학습** — post-training 데이터를 성공 에피소드로 걸러 씁니다. 자기 실패에서 개선하는 경로는 없습니다.
- **평가 규모와 재현성** — 실제 가정 3곳, 태스크당 10회, 부분점수 지표, 비공개 로봇과 데이터입니다. 결과도 그래프로만 제시되어 수치 비교가 어렵습니다.
- **메모리 없는 상위 정책** — 서랍 여닫기 루프는 현재 관측만 보고 다음 서브태스크를 고르는 상위 정책의 전형적인 실패로 보입니다. 논문이 인정한 "짧은 컨텍스트"와 뿌리가 같습니다.

## 8. 마치며 — 이 논문이 시사하는 것

**π₀.₅의 기여는 특정 모듈에 있지 않고, 이질적인 지식원을 층위별로 배치하는 학습 레시피가 open-world 일반화를 만든다는 것을 실제 가정에서 보여 준 데 있습니다.** 타깃 데이터가 2.4%인 믹스처로 처음 보는 집의 다단계 태스크를 해낸다는 결과는, 로봇 데이터 수집을 무한정 늘리는 것만이 스케일링의 길은 아님을 시사합니다.

이 논문은 LLM·diffusion·agentic AI 배경을 가진 사람에게 특히 잘 읽힙니다.

- **데이터 믹스처가 곧 기여입니다** — LLM의 사전학습·mid-training 믹스처 ablation과 같은 종류의 연구입니다.
- **학습은 토큰으로, 서빙은 연속 디코더로** — LLM 네이티브 목적(cross-entropy)으로 표현을 먼저 만들고, 서빙 제약(50Hz)에 맞는 연속 생성기를 나중에 붙입니다. 붙이는 부분은 MM-DiT식 모달리티별 가중치와 공유 attention, DiT식 adaptive norm 컨디셔닝, rectified-flow 목적과 10-step 샘플링으로, diffusion 연구자에게 익숙합니다.
- **한 모델 안의 planner–executor** — 서브태스크 문자열이 tool call 역할을 합니다. zero-shot GPT-4 planner가 최하위이고 사람 oracle마저 진다는 결과는 agentic 시스템에도 그대로 옮겨지는 교훈입니다. planner의 지능보다 **executor와의 정렬**이 먼저라고 판단됩니다.
- **추론 데이터의 학습 효과** — implicit HL은 추론 데이터를 학습에 넣는 것만으로 직접 행동이 좋아진다는 것을 보여 줍니다. CoT 데이터를 보조 학습 신호로 쓰는 LLM 연구와 나란히 놓고 볼 만합니다.

## 부록 — 용어 정리

| 용어 | 정의 |
|---|---|
| **co-training** | 로봇 액션 외에 웹 VQA, 서브태스크 예측 같은 이질적 과제를 한 모델에 함께 학습시키는 것 |
| **액션 청크** | 여러 시점의 액션을 한 번에 예측하는 단위. π₀.₅는 50스텝(50Hz에서 약 1초) |
| **FAST** | 액션 청크를 DCT로 압축하고 BPE로 토큰화하는 이산 액션 표현 |
| **action expert** | 액션 토큰만 처리하는 별도 가중치 세트(300M). flow matching으로 연속 액션을 생성함 |
| **상위 추론 (HL)** | 관측과 전체 명령으로부터 다음 서브태스크를 텍스트로 생성하는 것 |
| **VI (verbal instruction)** | 사람이 학습된 저수준 정책을 언어로 단계별 지휘하며 수집한 상위 명령 시연 |
| **MM / ME / CE / WD** | 모바일 매니퓰레이터 / 다환경 고정팔 / 실험실 cross-embodiment / 웹 데이터 |
| **implicit HL** | 추론 시 서브태스크를 생성하지 않지만 HL 데이터로는 학습한 변형 |
| **knowledge insulation** | expert에서 백본으로 가는 gradient를 stop-gradient로 끊어 사전학습 지식을 보호하는 후속 기법 |
