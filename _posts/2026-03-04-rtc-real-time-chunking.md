> **핵심 주장** — 추론 지연은 가속만으로는 없앨 수 없습니다. 다만 다음 행동 청크를 실행과 병렬로 생성하면서 추론하는 동안 이미 실행될 행동은 고정하고 나머지를 inpainting으로 채우면, **재학습 없이 청크 경계의 연속성과 새 관측에 대한 반응성을 함께 얻을 수 있습니다.**

---

## 들어가며

VLA의 추론 파이프라인은 거대한 VLM 백본, KV cache prefill, 여러 스텝에 걸친 반복 생성까지 LLM에서 많은 것을 물려받았습니다. 다만 **LLM에서 추론 속도가 사용자 경험의 문제였다면, 로봇에서는 물리의 문제입니다.** 챗봇이 느리면 사용자가 답답할 뿐이지만, 로봇 정책이 느리면 들고 있던 뜨거운 커피를 쏟습니다(논문 intro의 비유).

RTC(Real-Time Chunking)는 이 간극을 정면으로 다룹니다. 새 모델도, 새 학습 레시피도 제안하지 않고, 이미 학습된 flow/diffusion VLA를 **어떻게 실행할 것인가**만 바꿉니다. 그 핵심 도구는 diffusion을 아는 사람에게 매우 익숙한 **inpainting**입니다. 이 글에서는 논문의 논지를 따라가면서, 각 설계 결정의 이유를 이해하는 데 필요한 개념을 그 자리에서 정리했습니다.

## 1. 문제 — 로봇이 생각하는 동안에도 세계는 움직인다

### 1.1 지연은 대형 VLA의 구조적 부산물이다

cyber-physical 시스템은 항상 실시간으로 동작합니다. 모델이 추론하는 동안에도 세계는 물리 법칙대로 흘러가고, 입력과 출력 사이의 지연은 그대로 성능에 반영됩니다. 문제는 VLA가 수십억 파라미터라 느리고, 모바일 로봇에 싣기 어려운 GPU를 요구해 원격 추론 오버헤드까지 붙는다는 점입니다. 논문이 제시한 수치는 다음과 같습니다.

| 모델 | 지연 | 비교 기준 |
|---|---|---|
| π0 (3B) | RTX 4090에서 KV cache prefill만 46ms (denoising 전) | 목표 50Hz → 제어 주기 20ms |
| π0 원격 추론 | 네트워크만 13ms (유선, 이상적 조건) | — |
| OpenVLA-OFT (7B) | 추론 속도를 최적화하고도 A100에서 321ms | — |

**prefill 하나만으로 제어 주기의 두 배를 넘습니다.**

### 1.2 Action chunking은 절반의 해답이다

현재 표준 해법은 **action chunking**입니다. 한 번의 추론으로 여러 스텝의 행동을 한꺼번에 내고, 그것을 이어서 실행합니다. 추론 횟수가 줄어드니 지연의 부담이 분산됩니다. **다만 지연 자체가 사라지지는 않습니다.** 청크를 다 쓰면 결국 다음 청크를 기다려야 하고, 청크를 길게 쓸수록 새 관측에 대한 반응은 늦어집니다.

이 논문이 넘어야 할 벽은 두 개입니다.

**⛔ 벽 1 — 추론 지연은 줄일 수는 있어도 없앨 수는 없습니다.** distillation, parallel decoding, 양자화 등 가속 연구는 풍부합니다. 다만 논문의 related work가 짚듯, 이들은 모두 **forward pass 한 번 아래로는 내려가지 못합니다.** 그 한 번이 제어 주기보다 길면 가속만으로는 실시간 제약을 맞출 수 없습니다. 게다가 로봇 데이터가 커질수록 최고 성능 VLA도 커질 것이므로 격차는 저절로 줄지 않습니다. 결국 추론과 실행을 겹치는 **비동기 실행**이 필요합니다.

**⛔ 벽 2 — 비동기로 가는 순간 청크 경계가 끊깁니다.** 다음 청크를 미리 계산하면, 그 청크는 추론 시작 시점의 관측만 보고 만들어지므로 추론하는 동안 실행될 행동을 모릅니다. 게다가 학습된 행동 분포는 멀티모달이라 인접한 두 청크가 서로 다른 전략(모드)을 고를 수 있습니다. 그 결과 경계에서 OOD 급가속이 생깁니다. 여러 예측을 평균내는 흔한 스무딩은 유효한 행동을 보장하지 못합니다.

여기에 제약이 두 개 붙습니다.

| 제약 | 의미 |
|---|---|
| **재학습 없이** | 기존 VLA의 가중치와 학습 레시피를 건드리지 않음 |
| **반응성을 잃지 않고** | 연속성만 챙기면 새 관측을 무시하는 open-loop가 됨 |

### 1.3 그래서 논문이 던지는 질문

> 이미 학습된 flow VLA를, 재학습 없이, 추론과 실행을 겹쳐 돌리면서도 **청크 경계의 연속성**과 **새 관측에 대한 반응성**을 동시에 지킬 수 있는가?

벽 1은 3.4절에서, 벽 2는 3.1절~3.3절의 설계와 4절의 분석에서 회수합니다.

## 2. 배경 — 문제를 시간 축 위에 올려놓기

### 2.1 Action chunking과 두 개의 horizon

$$\pi(A_t\mid o_t),\qquad A_t=[a_t,\ a_{t+1},\ \dots,\ a_{t+H-1}]$$

| 기호 | 의미 |
|---|---|
| $o_t$ | 제어 스텝 $t$의 관측 |
| $a_t$ | 제어 스텝 하나의 행동 (예: 관절 목표 위치) |
| $A_t$ | $o_t$로부터 생성한 행동 청크 |
| $H$ | **prediction horizon** — 한 번에 예측하는 행동 수 |
| $s$ | **execution horizon** — 그중 실제로 실행하는 수. $s\le H$, 보통 $s\approx H/2$ |

$s$는 길게 잡아도, 짧게 잡아도 대가가 있습니다.

- **$s$가 길면** — 새 관측이 늦게 반영되어 반응성이 떨어집니다.
- **$s$가 짧으면** — 청크를 자주 갈아타면서 모드 점프(mode-jumping)로 동작이 튑니다.

**연속성 vs 반응성.** 이 긴장이 논문 전체를 관통합니다. RTC가 이 트레이드오프를 어떻게 풀어내는지는 4절에서 다시 살펴봅니다.

### 2.2 Flow policy의 샘플링

$$A_t^{\tau+\frac1n}=A_t^\tau+\frac1n\,v_\pi(A_t^\tau,\ o_t,\ \tau),\qquad A_t^0\sim\mathcal N(0,I)$$

| 기호 | 의미 |
|---|---|
| $\tau\in[0,1)$ | flow 시간. **τ=0이 노이즈, τ=1이 데이터** (diffusion의 $t$와 방향이 반대) |
| $v_\pi$ | 학습된 속도장(velocity field) |
| $n$ | denoising 스텝 수. 이 논문의 실험은 모두 $n=5$ |

논문은 diffusion policy도 추론 시점에 flow로 변환하면 같은 방식으로 다룰 수 있다고 밝혔습니다. 이 글에서는 flow를 기준으로 설명합니다.

### 2.3 동기 vs 비동기 — 벽 2가 모습을 드러내는 곳

| 기호 | 의미 |
|---|---|
| $\Delta t$ | 제어 주기 (50Hz면 20ms) |
| $\delta$ | 청크 하나를 생성하는 데 걸리는 시간 |
| $d=\lfloor\delta/\Delta t\rfloor$ | **inference delay** — 관측을 받은 뒤 청크가 나올 때까지 지나가는 제어 스텝 수 |

실시간이란 "관측 $o_t$를 받은 뒤 $\Delta t$ 안에 $a_t$를 낸다"는 보장입니다. $\delta\le\Delta t$면 자명하지만, 1.1절의 수치대로 현대 VLA로는 거의 불가능합니다. 이 때문에 실행 전략이 두 갈래로 나뉩니다.

```
t :   0                        s-d               s
      |-------------------------|----------------|------------------>
SYNC  [=== A_0 : run s actions =================][ pause ~d ][ A_s ...
                                                 ^ observe o_s, then infer
ASYNC [=== A_0 : run s actions =================][ A_{s-d} ...........
                                ^ observe o_{s-d}, infer in parallel
                                                 ^ A_{s-d} ready -> swap
```

- **Synchronous** — $s$개를 실행한 뒤 멈추고 추론합니다. 많은 선행 연구의 기본값이며, 청크 사이에 눈에 보이는 정지가 생깁니다.
- **Asynchronous** — $s-d$ 시점에 추론을 시작해 실행과 병렬로 돌립니다. $d\le H-s$면 행동이 끊기지 않습니다. 다만 새 청크는 $o_{s-d}$만 보고 만들어져 $s-d$부터 $s$ 사이에 일어난 일을 모르므로, 경계 $a_{s-1\mid 0}\to a_{s\mid s-d}$가 임의로 불연속일 수 있고 지연이 클수록 악화됩니다.

여기서 $a_{t'\mid t}$는 관측 $o_t$로 만든 청크 $A_t$의 $(t'-t)$번째 행동입니다.

비동기의 문제는 분명합니다. 그렇다면 동기 방식은 느리기만 할 뿐 정확도에는 문제가 없다고 생각하기 쉽습니다.

> ### 💡 동기 추론의 정지는 속도 손실만이 아니다 — 동역학이 바뀐다
>
> 논문은 정지가 로봇의 동역학 자체를 바꿔 학습과 평가 사이에 분포 이동을 만든다고 지적하였습니다. 시연 데이터에는 1초마다 멈칫하는 로봇이 없습니다. 멈춘 사이 물체와의 접촉·관성 상태가 변하고, 다음 청크는 학습 때 본 적 없는 속도 프로파일(정지 → 재가속) 위에서 시작합니다.
>
> 더 극단적인 경우도 있습니다. 토크/힘 제어에는 "제자리 유지"라는 개념이 없습니다. 멈춰 있는 동안에도 중력과 관성이 계속 작용하기 때문입니다. 이 때문에 힘 기반 제어인 논문의 시뮬레이션(Kinetix)에는 synchronous baseline이 아예 없고, 비동기 변형끼리만 비교합니다. 반면 실로봇은 위치 제어라 synchronous가 합리적인 기본값이며, 실로봇 실험의 주 비교 대상이 됩니다(5.2절).

동기도 비동기도 문제라면, 비동기의 경계 불연속을 다른 방식으로 메우는 길을 찾아볼 수 있습니다. 가장 쉬운 발상은 겹치는 구간의 예측들을 평균내서 매끄럽게 잇는 것입니다. ACT가 제안한 **temporal ensembling(TE)** 이 바로 이것입니다. 논문의 Figure 2가 이 발상이 왜 실패하는지 보여줍니다.

```
               old chunk {a}  : ------------------>   plan: go OVER
              /
  robot  *---+                  [  OBSTACLE  ]
              \
               new chunk {a'} : ------------------>   plan: go UNDER

  naive async : a_10 (over) -> a'_11 (under)   => huge OOD acceleration
  TE (average): mean(over, under)              => straight into obstacle
```

- 이전 청크는 장애물 **위로**, 새 청크는 **아래로** 돌아가는 계획을 세웠습니다.
- naive async는 한 스텝 만에 위 궤도에서 아래 궤도로 점프합니다.
- TE는 두 궤도의 평균, 즉 장애물 정면으로 향합니다.

> ### 💡 멀티모달 분포에서 평균은 유효한 행동이 아니다
>
> 장애물을 위로 도는 것도, 아래로 도는 것도 유효한 모드입니다. 반면 둘의 평균은 정면 충돌입니다. diffusion 배경에서 보면 익숙한 이야기로, 서로 다른 두 얼굴 샘플을 픽셀 평균 내면 흐릿한 유령 얼굴이 나옵니다.
>
> 애초에 MSE 회귀 대신 diffusion/flow 정책을 쓰는 이유가 **모드 평균화를 피하기 위해서**였습니다. TE는 그 평균화를 실행 단계에서 다시 들여옵니다. 실제로 논문 시뮬레이션에서 TE는 지연이 0일 때조차 부진했고, 논문은 이를 벤치마크가 멀티모달이라는 증거로 해석하였습니다.

**정리하면, 벽 2를 넘으려면 새 청크가 이전 청크와 같은 모드를 유지하도록 생성 단계에서부터 조건화되어야 합니다.** 사후 평균으로는 해결되지 않습니다.

## 3. 방법 — 비동기 청킹을 inpainting으로 다시 쓰기

### 3.1 핵심 통찰 — 실행이 확정된 행동은 이미 "알려진 픽셀"이다

비동기 추론을 시작하는 순간을 생각해 보겠습니다. 새 청크의 앞 $d$개는 쓸모가 없습니다. 추론하는 동안 그 시간은 이미 지나가고, 그 자리는 이전 청크의 행동으로 채워지기 때문입니다. 즉 **앞 $d$개는 실행이 이미 확정된 값**입니다.

그렇다면 그 값을 고정해 두고, 나머지를 그와 정합되게 채우면 됩니다. **이미지의 가려진 영역을 주변과 어울리게 채우는 inpainting과 정확히 같은 구조입니다.** 새 청크의 인덱스를 기준으로 세 영역이 생깁니다.

```
index      | 0  ...  d-1 | d  .......  H-s-1 | H-s  ...  H-1
-----------+-------------+-------------------+---------------
prev chunk | a  a  a  a  | a  a  a  a  a  a  |
new chunk  | a' a' a' a' | a' a' a' a' a' a' | a' a' a' a' a'
weight W   | 1  1  1  1  | 1 -> exp -> 0     | 0  0  0  0  0
region     | frozen      | intermediate      | fresh
length     | d           | H - d - s         | s
```

- **frozen** ($d$개) — 추론하는 동안 이미 실행될 행동. 물리적으로 바꿀 수 없으므로 가중치 1
- **intermediate** ($H-d-s$개) — 이전 청크에 값은 있지만, 새 청크가 나온 **뒤에** 실행되므로 수정 가능. 점점 줄어드는 가중치
- **fresh** ($s$개) — 이전 청크의 끝 너머. 새로 생성하므로 가중치 0

논문 Figure 3의 예시는 $H=16,\ d=4,\ s=5$로, intermediate가 7개입니다.

**frozen은 덮어쓰기가 아닙니다.** 새 청크의 앞 $d$개는 이전 청크와 일치하도록 유도될 뿐 실제로 실행되지 않습니다. 청크를 교체하는 시점에 실행 인덱스가 이미 $d$만큼 진행되어 있어 새 청크의 index $d$부터 실행되기 때문입니다(Algorithm 1, 3.4절). frozen 구간은 나머지 행동을 끌어당기는 **앵커**입니다.

### 3.2 재학습 없는 inpainting — ΠGDM guidance

inpainting은 diffusion과 flow가 원래 잘하는 일입니다. RTC는 Pokle et al.의 training-free flow inpainting을 가져왔으며, 이 방법은 다시 pseudoinverse guidance(ΠGDM)에 기반합니다. 매 denoising 스텝마다 학습된 속도장에 guidance 항을 하나 더합니다.

$$v_{\Pi\text{GDM}}(A_t^\tau,o_t,\tau)=v(A_t^\tau,o_t,\tau)+\min\!\Big(\beta,\ \frac{1-\tau}{\tau\,r_\tau^2}\Big)\big(Y-\hat A_t^{1}\big)^{\top}\mathrm{diag}(W)\,\frac{\partial \hat A_t^{1}}{\partial A_t^\tau}$$

$$\hat A_t^1=A_t^\tau+(1-\tau)\,v(A_t^\tau,o_t,\tau),\qquad r_\tau^2=\frac{(1-\tau)^2}{\tau^2+(1-\tau)^2}$$

| 기호 | 의미 |
|---|---|
| $Y$ | 목표값 = 이전 청크의 남은 행동 (길이 $H$로 오른쪽 패딩) |
| $W$ | 위치별 가중치 마스크 (3.1절의 frozen / intermediate / fresh) |
| $\hat A_t^1$ | 현재 $A_t^\tau$에서 τ=1로 한 번에 점프한 "완성본 추정" |
| $r_\tau^2$ | 그 추정의 불확실성(분산) |
| $\beta$ | guidance 가중치 상한 (논문이 추가한 부분) |
| $\partial\hat A^1/\partial A^\tau$ | Jacobian. 앞의 행벡터와 곱하면 vector-Jacobian product(VJP)가 되어 backprop 한 번으로 계산됨 |

$Y,A,W$는 길이 $HM$($M$은 행동 차원)의 벡터로 취급합니다. 작동은 세 단계로 읽힙니다.

- **⓵ 완성본 추정** — 현재 노이즈 상태에서 최종 청크를 한 번 추정합니다. diffusion의 $\hat x_0$ 예측(DDIM의 predicted $x_0$)과 같은 역할입니다.
- **⓶ 가중 오차** — 추정된 완성본이 $W$가 가리키는 위치에서 이전 청크와 얼마나 다른지 잽니다.
- **⓷ 역전파** — 그 오차를 Jacobian으로 $A^\tau$ 공간으로 끌어와 속도장에 더합니다. 그러면 적분 궤적이 "다 완성됐을 때 prefix와 맞도록" 휘어집니다.

classifier guidance에서 classifier 자리에 "prefix 일치도"를 넣은 reconstruction guidance로 볼 수 있습니다.

그런데 가중치 $\frac{1-\tau}{\tau r_\tau^2}$는 τ=0에서 무한대가 됩니다. 논문은 β로 자른다고만 썼는데, 이 식이 어디서 왔고 β가 정확히 무엇을 자르는지는 따로 풀어 볼 필요가 있습니다.

> ### 💡 guidance 가중치는 (score→velocity 환산) × (추정의 신뢰도)다
>
> 논문은 이 가중치를 유도하지 않으므로 여기서 직접 풀어보겠습니다. 선형 경로 $A^\tau=\tau A^1+(1-\tau)\epsilon$에서 속도장과 score는 다음 관계에 있습니다.
>
> $$v(x,\tau)=\frac{x}{\tau}+\frac{1-\tau}{\tau}\,\nabla_x\log p_\tau(x)$$
>
> - $\nabla_x\log p_\tau(x)$: 시점 τ의 분포에 대한 score
> - $\frac{1-\tau}{\tau}$: score의 변화가 속도장의 변화로 환산되는 비율
>
> score에 likelihood 항 $\nabla\log p(Y\mid A^\tau)$를 더하면 속도장은 그 $\frac{1-\tau}{\tau}$배만큼 바뀝니다. ΠGDM은 $p(Y\mid A^\tau)$를 평균 $\hat A^1$, 분산 $r_\tau^2$인 가우시안으로 근사하므로 score 보정은 $\frac{1}{r_\tau^2}(Y-\hat A^1)^\top\mathrm{diag}(W)\frac{\partial\hat A^1}{\partial A^\tau}$가 되고, 둘을 곱하면 위 식의 가중치가 나옵니다. $r_\tau^2$는 데이터를 표준 가우시안으로 가정했을 때 $A^\tau$를 본 뒤 $A^1$에 남는 사후 분산입니다.
>
> 정리하면 가중치는 깔끔한 형태가 됩니다.
>
> $$w(\tau)=\frac{1-\tau}{\tau\,r_\tau^2}=\frac{\tau}{1-\tau}+\frac{1-\tau}{\tau}$$
>
> τ=0.5에서 최솟값 2, 양 끝에서 발산하는 U자 곡선이며, 이 곡선이 β의 역할을 정확히 설명합니다. $n=5$면 τ∈{0, 0.2, 0.4, 0.6, 0.8}이고, τ=0에서만 무한대이며 나머지의 최댓값은 τ=0.2와 0.8에서의 4.25입니다. 논문 Figure 7 캡션의 4.25와 일치합니다. 즉 논문이 쓰는 β=5는 사실상 **첫 스텝(τ=0)의 가중치만 5로 정하는** 설정입니다.
>
> **β는 이미지 기법을 few-step 영역으로 옮기면서 필요해진 안정화 장치입니다.** 이미지 inpainting이 n=100 수준이라 스텝당 보정 폭이 작았다면, 제어는 n=5라 한 스텝의 guidance가 크고, 과하면 청크가 발산합니다(App. A.2). 실제로 β를 키울수록 실로봇 청크의 최대 가속도가 커졌고, 시뮬레이션에서는 β=5 이상에서 추가 이득이 없었습니다.

**비용.** 매 스텝 VJP를 계산하므로 역전파가 붙습니다. 다만 역전파는 **action expert만** 통과합니다. 이미지·언어 prefix의 KV cache는 $A^\tau$와 무관하기 때문입니다. π0.5의 프로파일링(Table 3, RTX 4090, bfloat16)이 이를 보여줍니다.

| 구성 요소 | vanilla π0.5 | + RTC |
|---|---|---|
| Image encoder (SigLIP) | 18ms | 18ms |
| LLM prefill (Gemma 2B) | 44ms | 44ms |
| Denoising ×5 | 14ms | 35ms (스텝당 2.5×) |
| **합계** | **76ms** | **97ms** |

지연의 대부분은 여전히 백본이고, RTC가 얹는 21ms는 약 300M 규모의 action expert(π0 계열 구조 기준, App. A.3)에서만 발생합니다.

그래도 스텝당 2.5배는 가볍지 않습니다. 굳이 역전파까지 하지 않고 prefix 위치를 매 스텝 원하는 값으로 덮어쓰기만 하면 훨씬 싸다는 반론이 가능합니다.

> ### 💡 prefix를 덮어쓰기만 해서는 나머지가 따라오지 않는다
>
> 논문은 App. A.4에서 Diffuser식 inpainting(매 denoising 스텝마다 알려진 구간을 원하는 값으로 덮어쓰는 방식)을 같은 설정에 적용해 비교하였습니다. naive async보다는 낫지만 guidance 방식에는 뒤처집니다.
>
> 이유는 정보가 전달되는 경로에 있습니다. 덮어쓰기는 알려진 위치의 값만 바꾸고, 나머지 위치가 그에 맞춰지는 일은 다음 스텝에서 네트워크가 알아서 해주길 기대하는 **간접 전달**입니다. 반면 guidance는 "완성본의 prefix 불일치"를 Jacobian으로 모든 위치에 **직접** 역전파하므로, intermediate와 fresh 영역까지 prefix와 정합되도록 조정됩니다. 이미지 쪽에서 replacement 방식이 경계 부조화 문제 때문에 RePaint의 resampling 같은 보완을 필요로 했던 것과 같은 계열의 문제입니다.

### 3.3 Soft masking — 겹치는 구간 전체를 앵커로 쓴다

**frozen $d$개에만 가중치 1을 주는 hard masking으로는 부족했습니다.** ΠGDM 보정은 근사이고, 특히 $d$가 작으면 제약 위치가 적어 guidance 신호가 약합니다. 그러면 새 청크가 여전히 전략을 바꿔버릴 수 있습니다. 논문 Figure 4에서 hard masking은 frozen 구간조차 잘 맞추지 못했고 방향 전환도 급했습니다.

해법은 frozen $d$개 대신 **겹치는 $H-s$개 전부**를 쓰되, 먼 미래일수록 불확실하므로 가중치를 감쇠시키는 것입니다.

$$W_i=\begin{cases}1 & i<d\\ c_i\,\dfrac{e^{c_i}-1}{e-1} & d\le i<H-s\\ 0 & i\ge H-s\end{cases},\qquad c_i=\frac{H-s-i}{H-s-d+1}$$

| 기호 | 의미 |
|---|---|
| $i$ | 새 청크 내 인덱스, $0\le i\le H-1$ |
| $c_i$ | intermediate 구간에서 1 근처 → 0 근처로 선형 감소하는 진행도 |
| $W_i$ | 이전 청크의 $i$번째 행동에 주는 "주의(attention)" 가중치 |

실로봇 설정($H=50,\ s=25,\ d=6$)에서 계산해 보면 감쇠가 꽤 빠릅니다.

| $i$ | 6 | 10 | 15 | 20 | 24 |
|---|---|---|---|---|---|
| $W_i$ | 0.88 | 0.49 | 0.19 | 0.04 | 0.001 |

이 마스크가 곧 2.1절의 긴장을 조절하는 장치입니다.

| 영역 | 이전 청크에 대한 태도 |
|---|---|
| frozen | 물리적으로 강제되어 반드시 따름 |
| intermediate | 되도록 이전 계획을 따르되, 새 관측이 충분히 다르면 벗어날 수 있음 |
| fresh | 자유롭게 새 관측만으로 생성함 |

감쇠 스케줄 비교(App. A.4)에서는 exponential이 가장 좋았고 linear가 근소한 차이로 뒤따랐습니다. 감쇠 없이 겹치는 구간 전체에 1을 주는 방식과 hard masking은 둘 다 뒤처졌습니다.

### 3.4 전체 시스템 — 지연을 숨기는 두 개의 스레드

전체 시스템(Algorithm 1)은 두 스레드가 mutex로 상태를 공유하는 구조입니다.

| 구성 | 역할 |
|---|---|
| `GETACTION` | 제어기가 매 $\Delta t$마다 호출. 행동 하나를 내주고 최신 관측을 저장 |
| `INFERENCELOOP` | 백그라운드 스레드. 실행 카운터가 $s_{\min}$에 도달하면 추론을 시작하고, 끝나는 즉시 청크를 교체 |
| `GUIDEDINFERENCE` | $W$ 계산, 이전 청크 패딩, $n$스텝 guided 적분 |

운영 디테일은 세 가지입니다.

- **⓵ 지연의 보수적 예측** — 최근 $b$개(실로봇 10개) 실측 지연의 **최댓값**을 다음 $d$로 씁니다.
- **⓶ 청크마다 달라지는 $s$** — 실제 $s=\max(d,\ s_{\min})$이며, 실로봇에서 $s_{\min}=25$입니다.
- **⓷ $d\le s\le H-d$ 유지** — 하한은 다음 추론이 현재 추론이 끝난 뒤에야 시작할 수 있기 때문입니다. 상한은 청크 하나가 자기 추론 시작 기준 index $d$부터 다음 청크가 도착하는 $s+d-1$까지 행동을 공급해야 하기 때문입니다($s+d\le H$).

**여기서 벽 1이 회수됩니다.** RTC는 가속으로 forward pass 한 번의 벽을 넘으려 하는 대신, 그 벽을 실행 뒤에 숨깁니다. 지연을 줄이기는커녕 76ms에서 97ms로 **늘리지만**, $d\le H-s$인 한 지연을 **보이지 않게 숨깁니다.** π0.5의 청크는 $H=50$ × 20ms = 1초이므로, +200ms를 주입해 $d\approx16$(청크의 32%)이 되어도 여유 있게 제약 안에 들어옵니다.

> ### 📌 RTC의 차별점 — 지연을 줄이는 대신 숨기고, 그 대가인 경계 불연속을 inpainting으로 지불한다
>
> - **추론 시점 전용** — 기존 flow/diffusion VLA의 가중치와 학습 레시피를 그대로 씁니다.
> - **문제의 재정의** — 비동기 청킹을 "실행이 확정된 prefix에 조건부인 생성", 즉 inpainting으로 봅니다. 논문은 inpainting이나 guidance를 실시간 제어에 적용한 첫 사례라고 주장하였습니다.
> - **이미지 기법의 few-step 이식** — 그대로는 작동하지 않았고, soft masking(약한 신호의 보강)과 β clipping(발산 방지)이라는 두 가지 수정이 필요했습니다.

## 4. 왜 작동하는가 — 벽 2와 트레이드오프의 회수

논문의 자기설명은 세 갈래로 정리됩니다.

| 축 | 담당 장치 | 효과 |
|---|---|---|
| **⓵ 연속성** | frozen 구간 guidance | 경계의 OOD 급가속이 사라짐 |
| **⓶ 전략 일관성** | soft mask | guidance 신호를 겹치는 구간 전체로 넓혀 모드 전환을 억제함 |
| **⓷ 반응성** | 최신 관측 조건화 + 감쇠 가중치 | intermediate·fresh 구간에 새 정보가 반영될 여지가 남음 |

**⓵과 ⓶로 벽 2가 회수됩니다.** 청크 경계를 사후에 스무딩하지 않고, 새 청크가 처음부터 이전 청크와 같은 모드 위에서 생성되도록 만든 것입니다.

**가장 설득력 있는 증거는 2.1절에서 예고한 연속성 vs 반응성 트레이드오프가 해소되는 장면입니다.** 지연을 $d=1$로 고정하고 $s$를 1~7로 바꾼 실험(Figure 5 좌하단)에서, RTC와 BID만 $s$가 짧아질수록 성능이 **단조 증가**했습니다. 보통은 $s$를 줄이면 모드 점프가 늘어 손해입니다. 반면 연속성이 보장되면 $s$를 줄이는 것이 순수하게 "더 자주 새 관측을 반영하는" 이득이 됩니다. 즉 연속성을 확보하자 반응성을 공짜로 살 수 있게 된 것입니다.

실로봇에서도 같은 흐름이 보입니다. 정지 시간을 제외한 순수 제어 스텝 기준으로도 RTC가 태스크를 더 빨리 진행했고, 논문은 이를 실수와 재시도가 줄어든 결과로 해석하였습니다. 다만 이것은 "정지가 분포 이동을 만든다"는 논문의 추론과 맞물린 해석이며, 분포 이동을 직접 측정한 것은 아닙니다.

그런데 LLM 배경에서 보면 이상한 점이 하나 있습니다. LLM도 스트리밍 중에 다음 문장을 생성하지만, 이미 출력한 말과 모순될까 봐 별도의 장치를 두지는 않습니다. VLA에서는 이것이 왜 논문 한 편 분량의 문제가 되는지 짚어 보겠습니다.

> ### 💡 AR 모델에게 prefix 이어쓰기는 공짜지만, 청크 단위 flow 모델에게는 그 입구가 없다
>
> **LLM** 은 $p(x_k\mid x_{<k})$로 학습되므로, 이미 출력해 되돌릴 수 없는 토큰에 자동으로 조건부입니다. 이어지는 말이 앞말과 정합되는 것은 모델 구조가 보장합니다.
>
> **Flow VLA** 는 $\pi(A_t\mid o_t)$로 청크 $H$개를 관측에만 조건부로 한 번에 뽑습니다. 학습할 때 "직전 청크에서 실행이 확정된 행동"은 입력에 없습니다. 그것을 조건으로 걸 **입구 자체가 없는 것**입니다.
>
> RTC가 하는 일은 학습된 적 없는 조건부 분포를 추론 시점에 guidance로 근사 샘플링하는 것입니다.
>
> $$A_t\ \sim\ \pi\big(A_t\ \mid\ o_t,\ A_{\text{prefix}}\big)$$
>
> - $A_{\text{prefix}}$: 이전 청크의 남은 행동 ($W$ 가중으로 반영)
> - 이 분포는 한 번도 학습되지 않았습니다. RTC는 무조건부 모델 위에 guidance로 **사후적으로 조건을 답니다**.
>
> 음성 에이전트에 비유하면, frozen 구간은 "이미 입 밖으로 나간 말"이고 intermediate 구간은 "하려고 했지만 아직 바꿀 수 있는 말"입니다. 그렇다면 자연스러운 다음 수는 이 조건을 **학습 시점에** 넣는 것이며, 6절에서 그 방향의 후속 연구를 살펴봅니다.

## 5. 실험

### 5.1 시뮬레이션 — 동적 태스크만 모은 Kinetix 벤치마크

기존 시뮬레이션 모방학습 벤치마크는 대부분 준정적(quasi-static)이라, 긴 $s$로 사실상 open-loop 실행만 해도 거의 포화됩니다. 즉 지연의 영향을 드러낼 수 없는 환경입니다. 이 때문에 논문은 힘 기반 제어 시뮬레이터 Kinetix로 새 벤치마크를 만들었습니다. 기존 환경 10개와 신규 2개를 합친 12개 환경으로, 던지기·받기·균형 잡기 같은 동적 조작과 보행(half-cheetah, walker 등)을 포함합니다. 행동에 가우시안 노이즈를 더해 closed-loop 보정이 필수가 되도록 했습니다.

| 항목 | 설정 |
|---|---|
| 전문가 | RPO + 이진 성공 보상, 환경당 seed 6개 |
| 데이터 | 1M transition. 에피소드마다 다른 전문가를 써서 멀티모달 데이터를 만듦 |
| 정책 | flow policy, $H=8$, 4-layer MLP-Mixer, 32 epoch |
| 평가 | 데이터 포인트당 2048 rollout, 95% Wilson interval |
| 지연 | $d\in\{0,\dots,4\}$ ($H=8$에서 가능한 최대가 4) |

비교군은 세 가지입니다.

| 비교군 | 동작 |
|---|---|
| Naive async | 이전 청크를 전혀 보지 않고, 새 청크가 준비되는 즉시 교체 |
| BID | rejection sampling으로 청크 간 연속성 유지. N=32, K=3, 8 epoch 체크포인트를 weak 모델로 사용 |
| TE | 같은 시점에 대한 여러 청크의 예측을 평균 |

결과는 그래프로만 제시되어 있어 정성적으로 정리합니다(Figure 5, 7, 8).

- **TE** — 지연이 0일 때조차 부진합니다. 2.3절의 "평균은 유효한 행동이 아니다"를 그대로 확인합니다.
- **RTC** — 지연 증가에 가장 강건하며, BID와의 격차는 지연이 클수록 벌어집니다.
- **hard vs soft masking** — hard가 뒤처지며, 특히 $d$가 작을 때 차이가 큽니다. 3.3절의 주장을 뒷받침합니다.
- **ablation** — β는 5 이상에서 추가 이득이 없고, 감쇠 스케줄은 exponential ≳ linear이며, Diffuser식 inpainting은 RTC에 못 미칩니다.

논문은 RTC가 BID를 이기면서도 연산을 훨씬 적게 쓴다고 강조하였습니다. 다만 이 비교는 조건과 함께 읽어야 합니다.

> ### ⚠️ 팩트체크 — "BID보다 낫고 연산은 훨씬 적다"는 연산량을 맞춘 비교가 아니다
>
> - 시뮬레이션의 BID는 스텝당 청크 64개(strong 32 + weak 32)를 샘플합니다. RTC가 이긴 것은 사실이지만, 같은 연산 예산에서의 비교는 없습니다.
> - 실로봇에서 BID를 제외한 근거인 "2.3배 지연"은 full BID(223ms) 기준입니다. forward contrast를 뺀 경량 BID는 115ms로 RTC(97ms)의 약 1.2배입니다(Table 1). 이 경량 변형의 성능은 보고되지 않아, 실로봇에서 BID를 뺀 판단이 타당했는지는 확인할 근거가 없습니다.

### 5.2 실로봇 — π0.5, 양팔 6-DoF

**설정.** π0.5($H=50$, $\Delta t$=20ms, $n=5$)를 base로, 두 개의 6-DoF 팔과 평행 그리퍼로 구성된 양팔 시스템에서 평가하였습니다. 모델 지연은 baseline 76ms, RTC 97ms이고, LAN 원격 추론이 10~20ms를 더해 기본 $d\approx6$입니다. 실측 end-to-end 지연은 고정형 109ms, 모바일 139ms였습니다(Table 2). 여기에 더 큰 모델이나 먼 클라우드 서버를 가정해 **+100ms($d\approx11$)와 +200ms($d\approx16$)** 를 인위적으로 주입했습니다.

| 태스크 | 단계 | 제한 시간 | 특징 |
|---|---|---|---|
| Light candle | 5 | 40s | 성냥을 그어 초에 불붙이기. 가장 정밀하고, 유일하게 재시도가 불가능 |
| Plug ethernet | 6 | 120s | 케이블 끝을 재배향해 서버랙에 삽입, 양쪽 반복 |
| Make bed (mobile) | 3 | 200s | 담요 모서리와 베개 2개 이동. 전체 중 가장 어려움 |
| Shirt folding | 1 | 300s | 펼쳐진 셔츠 접기 |
| Batch folding | 4 | 300s | 구겨진 옷을 꺼내 펴고 접어 쌓기 |
| Dishes in sink (mobile) | 8 | 300s | 물건 4개를 싱크대로 옮기기 |

| 비교군 | 동작 |
|---|---|
| Synchronous | 25개 실행 후 멈추고 추론 (선행 연구의 기본값) |
| TE, sparse | $s=25$, 병렬 추론 + 겹치는 구간에 TE 적용 |
| TE, dense | 가능한 한 자주 추론($s=d$). 원래 ACT의 TE에 가장 가까움 |

평가는 태스크 × 방법 × 지연 조합당 10회, 총 480 에피소드(순수 실행 시간 28시간)입니다. 480 = 6 태스크 × 8 조합 × 10인데, TE 두 변형이 +0ms에서만 실행 가능했기 때문입니다(RTC 3 + Synchronous 3 + TE 2). 지표는 **throughput** 으로, 에피소드별 (완료한 단계 비율) ÷ (소요 시간)의 평균이며 속도와 성공을 함께 반영합니다.

| 관찰 | 내용 |
|---|---|

## 6. 위치잡기 — 이웃 연구들 속에서

RTC는 네 흐름의 교차점에 있습니다.

**⓵ Action chunking → VLA.** ACT와 Diffusion Policy 이후 action chunking은 visuomotor 모방학습의 사실상 표준이 되었고, π0/π0.5, OpenVLA, Octo, GR00T 같은 VLA로 스케일되었습니다. 논문은 저수준 PID 위에서 도는 청킹 정책을 cascade control의 바깥 루프로 볼 수 있다고 언급했지만, 그 교차점은 후속 과제로 남겼습니다.

**⓶ 지연 자체를 줄이는 연구.** consistency policy(증류), streaming diffusion policy, OpenVLA-OFT(parallel decoding), 그리고 PagedAttention·양자화 같은 LLM 서빙 최적화 전반이 여기에 속합니다. 모두 forward pass 한 번 아래로는 못 내려간다는 것이 벽 1의 근거였습니다. 이들은 RTC와 경쟁하기보다 서로 보완하는 관계입니다.

**⓷ Inpainting과 guidance.** Pokle et al., ΠGDM, RePaint 등 이미지 inverse problem 솔버, 그리고 planning에서 replacement 방식 inpainting을 쓴 Diffuser가 여기에 속합니다. RTC는 이 중 guidance 방식을 실시간 제어로 가져왔습니다.

**⓸ 실시간 실행.** 구조적으로 가장 닮은 것은 **MPC**입니다. 실행과 계산을 병렬화하고, 이전 계획으로 다음 계획을 warm-start한다는 점이 같습니다. 다만 MPC가 명시적 동역학 모델과 비용 함수를 요구하는 방식이라면, RTC는 "모델 없는 모방학습 정책판 receding-horizon warm-start"로 읽을 수 있습니다. 한편 System 2(느린 계획)와 System 1(빠른 행동)으로 나누는 계층형 VLA는 직교하는 접근으로, System 1의 크기가 제한되고 별도 학습 레시피가 필요하다는 트레이드오프가 있습니다.

청크 경계의 연속성을 확보하는 방법들을 나란히 놓으면 RTC의 위치가 선명해집니다.

| 방법 | 연속성 확보 수단 | 추가 비용 | 논문 내 결과 | LLM 쪽 대응물 |
|---|---|---|---|---|
| TE (ACT) | 같은 시점 예측들을 평균 | 거의 없음 | 시뮬 $d=0$에서도 부진, 실로봇 고지연에서 실행 불가 | 여러 샘플 출력의 평균 |
| Diffuser식 inpainting | 알려진 구간을 매 스텝 덮어쓰기 | 거의 없음 | 이득은 있으나 RTC 미만 | prefix 강제 삽입 |
| BID | 배치 샘플 후 rejection sampling | 배치 샘플 + 모델 2벌 | RTC 미만, 지연 클수록 격차 확대 | best-of-N reranking |
| **RTC** | ΠGDM guidance + soft mask | 스텝당 VJP (denoising 2.5×) | 전 구간 최고 | guided decoding |

가장 가까운 선행 연구는 BID입니다. 논문도 BID가 지연을 고려하지는 않았지만 같은 효과를 낼 수 있는 방법이라고 인정하였습니다. **둘의 차이를 표의 한 줄로 요약하면, BID가 여러 개를 뽑아서 고르는 방식이라면 RTC는 하나를 뽑으면서 휘는 방식입니다.**

마지막으로 3.2절의 비용 문제로 돌아가 보겠습니다. RTC의 오버헤드는 전부 "학습된 적 없는 조건을 추론 시점에 guidance로 근사한다"는 데서 나옵니다. 4절에서 예고했듯, 그 조건을 처음부터 학습에 넣는 방법을 생각해 볼 수 있습니다.

> ### 🔗 Training-Time RTC (Black et al., 2025-12) — 같은 조건을 학습 시점으로 옮기다
>
> 같은 연구진의 후속작(arXiv:2512.05964)은 학습 중에 추론 지연을 시뮬레이션하고 action prefix에 직접 조건화하는 방식으로, 추론 시점 inpainting의 오버헤드를 없애는 방법을 제시하였습니다. 모델 구조나 로봇 런타임 수정 없이 몇 줄의 코드로 구현됩니다.
>
> | | **RTC (본 논문)** | **Training-time RTC** |
> |---|---|---|
> | prefix 조건을 거는 시점 | 추론 (guidance) | 학습 (지연 시뮬레이션) |
> | 추론 오버헤드 | 스텝당 VJP | 없음 |
> | 재학습 | 불필요 | 필요 |
> | 보고된 결과 (초록 기준) | — | 시뮬레이션 고지연에서 RTC 능가, π0.6 실로봇에서 성능·속도 동등 |

## 7. 한계

**논문이 인정한 한계**

| 한계 | 내용 |
|---|---|
| 연산 오버헤드 | base 정책에서 직접 샘플링하는 것보다 상당히 무거움 (76 → 97ms) |
| 적용 범위 | diffusion/flow 정책 전용. AR 토큰 기반 VLA에는 그대로 쓸 수 없음 |
| 실환경의 동적 범위 | 보행처럼 더 동적인 설정은 시뮬레이션에만 있음 |
| 단순화 가정 | 제어 스텝 이하 수준의 지연·동기화 문제는 고려하지 않음 |

**추가로 짚을 지점**

- **트레이드오프는 사라지지 않고 재배치되었습니다.** intermediate 가중치는 샘플을 이전 계획 쪽으로 당깁니다. 이 때문에 갑작스러운 외란(물체가 밀리는 등)에 대한 반응 속도가 $W$의 감쇠 스케줄에 묶입니다. 실로봇에서 외란 반응을 직접 측정한 실험은 없고, 시뮬레이션의 행동 노이즈가 간접 증거일 뿐입니다.
- **ΠGDM은 근사입니다.** 가우시안 사후분산과 one-step 추정 $\hat A^1$에 기대므로, $n=5$에서 prefix 일치는 근사적입니다. frozen 구간은 어차피 실행되지 않으므로 근사 오차는 교체 지점(index $d$)의 작은 불연속으로 드러나고, soft mask가 이를 완화하는 구조로 보입니다.
- **이득은 지연이 클 때 집중됩니다.** 현재 하드웨어와 LAN 조건에서는 유의한 차이가 확인되지 않았습니다(5.2절).
- **네트워크 조건의 검증 범위.** 검증은 LAN과 인위적으로 주입한 고정 지연뿐입니다. 지연 예측이 최근 10개의 최댓값이므로, 지터가 큰 WAN이나 패킷 손실 상황에서의 동작은 별도로 확인해야 합니다.

## 8. 마치며 — 이 논문이 시사하는 것

**RTC의 기여는 새 모델을 제안하지 않고 실행 방식을 재정의한 데 있습니다.** 추론 지연을 가속으로 없애려는 대신 실행 뒤에 숨기고, 숨기면서 생기는 경계 불연속을 조건부 생성 문제로 바꿔 풉니다. 모델이 커질수록 지연도 커질 것이므로, 이 관점의 가치는 시간이 지날수록 커진다고 판단됩니다.

이 논문은 LLM·diffusion 배경을 가진 사람에게 유난히 잘 읽힙니다.

- **이미지 inverse problem 솔버의 직접 이식** — 행동 청크는 $H\times M$ 크기의 "1D 이미지"이고, ΠGDM 같은 training-free 솔버가 거의 그대로 넘어옵니다. 다만 이미지 기법은 n≈100을 전제로 하므로, few-step 영역에서는 β 같은 안정화가 필요합니다. 이미지 생성 연구의 경험이 로봇 제어에 직접 전이되는 드문 지점입니다.
- **LLM 서빙과의 분업** — π0.5 지연 76ms 중 62ms가 SigLIP과 Gemma prefill입니다. 양자화·캐시 같은 서빙 최적화가 $\delta$를 줄인다면, RTC는 남은 $\delta$를 숨깁니다. GPU의 latency hiding이나 prefetch 파이프라이닝과 같은 사고방식입니다.
- **Agentic AI로의 일반화** — "실행 중인 행동을 frozen prefix로 두고 그에 이어 다음 계획을 세운다"는 패턴은, 느린 planner가 실행과 병행해 생각해야 하는 모든 에이전트에 적용되는 설계 원리입니다. 음성 에이전트가 이미 발화한 문장과 정합되게 다음 문장을 이어가는 문제와 구조가 같습니다.

**무엇보다, +200ms(청크 길이의 32%)까지 성능 저하가 없었다는 결과는 로봇에 GPU를 싣지 않고 원격·클라우드 추론으로 대형 VLA를 돌리는 구성이 현실적인 선택지가 될 수 있음을 뜻합니다.** 7절에서 짚었듯 실제 WAN 조건에서의 검증은 남아 있지만, "VLA는 로봇 옆에 있어야 한다"는 전제를 흔드는 결과임은 분명합니다.

## 부록 — 용어 정리

| 용어 | 정의 |
|---|---|
| **action chunking** | 한 번의 추론으로 $H$스텝의 행동 청크를 내고 그중 $s$개를 실행하는 방식 |
| **prediction / execution horizon** | 청크 길이 $H$ / 실제 실행 길이 $s$ |
| **inference delay** | 관측을 받은 뒤 청크가 나올 때까지 지나가는 제어 스텝 수 $d=\lfloor\delta/\Delta t\rfloor$ |
| **synchronous / asynchronous inference** | 멈추고 추론 / 실행과 병렬로 추론 |
| **temporal ensembling (TE)** | 같은 시점에 대한 여러 청크의 예측을 평균하는 스무딩 |
| **frozen / intermediate / fresh** | 새 청크의 세 영역: 실행 확정 / 수정 가능한 겹침 / 새로 생성 |
| **ΠGDM guidance** | 완성본 추정과 목표의 불일치를 Jacobian으로 역전파해 속도장에 더하는 training-free inpainting |
